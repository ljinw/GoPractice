# 标准库最小Harness教学样例

这个程序只使用Go标准库、内存笔记与固定脚本。它展示三次模型式调用、两次工具执行、调用标识配对、失败回传、次数限制和协作取消检查。不访问文件系统资料，不调用供应商，不执行外部命令，不需要API Key。

固定脚本在代码中预知两个工具名称；没有实现自动schema登记或向供应商传输工具说明。

它不是DSH或Eino的移植，也不包含持久化、恢复、并发工具、流式输出、审批、真实权限系统、费用统计或完整事件日志。

## 运行位置与命令

在本目录执行，模块声明Go 1.22。本次使用Go 1.24.0 Linux/amd64验证；Windows/macOS上按同一命令实际运行后再登记结果。

```sh
go run .
go test -v ./...
```

预期看到用户问题、c1列笔记、c1结果、c2读笔记、c2结果、最终回答。回答依据functions.md中的“多返回值还不懂”。这是脚本根据固定结果生成的教学文字，不是真实模型分析。

## 先只读三处

1. `Call`：工具名、参数和调用标识放在哪里。
2. `Run`：模型回复分成文字与工具请求两条路径，结果怎样加入history。
3. `executeTool`：未知工具、无效参数、越界笔记怎样被拒绝。

`Model`接口让运行器依赖能力；`ScriptedModel`提供固定实现。测试使用不同模型替身制造错误，工具执行仍然运行真实教学实现。后续接Eino时更换模型/运行适配，不要假设本接口就是Eino的实际接口。

## 三个可重复的故障实验

```sh
go run . -steps 2
go run . -tools 1
go run . -cancel
```

这三条命令预期以非零状态结束，分别报告模型次数上限、工具次数上限、已取消。第一条仍会保存已经取得的工具结果；第二条不会执行超出预算的工具；第三条在首次模型调用前结束。

预期非零是本实验需要观察的行为，不是要求你把错误消息删掉。`go run`还可能打印`exit status 1`，这是运行器进程的退出状态。

## 按周末拆成四次，不必一次读懂

第一次只运行正常流程，按H01表格对照。第二次读工具输入与返回，再修改内存笔记内容。第三次研究次数限制与取消，用测试确认边界。第四次关掉参考，自己写一个只有单工具的简化版。

这个完整参考放在examples目录，不是替你完成原有练习。独立实现时另建个人练习目录，记录用了多少提示。

## 测试覆盖与边界

测试覆盖正常工具配对、未知工具、非法/未知/多余JSON参数、固定笔记范围、模型与工具次数限制、模型错误、取消前置与迟到成功、历史保护、错误回复及重复调用标识。

取消是协作机制。工具若无限阻塞且不响应ctx，本样例不能强制终止它。样例的内存白名单也不等于真实磁盘目录隔离。没有测试真实模型质量、DSH运行、Eino集成或生产部署。
