## 为什么保存文件后还需要版本管理

假设你让 Agent 给学习助手增加“保存报告”。它改了四个文件，功能暂时能跑。第二天又加了自动命名，旧功能开始覆盖文件。现在你想知道：是哪一次修改带来的？原先能工作的版本是什么？

编辑器保存主要解决“这次编辑写到磁盘”。版本管理还要解决“变化是什么、哪些变化属于同一件事、以前是什么样”。它像配置变更记录，但会精确保存文件内容的版本关系。

先认识三个位置：正在编辑的工作区；准备组成下一次提交的暂存区；已经提交的历史。暂存区在本地仓库里，不能简单理解为另一台服务器或内存缓存。

## 用两次小改动理解三个位置

假设 `main.go` 原来只打印一句话。你先把文字改了，又新增一个 `notes.md`。此时工作区有两项变化，但历史还没变化。

你只把 `main.go` 加入暂存区，意思是下一次提交先记录这个文件当前选中的内容。`notes.md` 仍留在工作区。提交成功后，历史多了一份快照；没有暂存的变化不会自动跟着提交。

若暂存后又编辑 `main.go`，工作区与暂存区里同一文件还可能不同。因此“这个文件已经 add 过”不等于最新编辑一定进入下一次提交。

| 想知道什么 | 只读命令 | 看哪一类差异 |
|---|---|---|
| 当前有哪些变化 | `git status` | 文件处在哪个状态 |
| 暂存后又改了什么 | `git diff` | 工作区相对暂存区 |
| 准备提交什么 | `git diff --cached` | 暂存区相对当前提交 |
| 最近记录了什么 | `git log --oneline -5` | 提交历史 |

命令在实际 Git 仓库目录运行。没有差异时 `git diff` 可以没有输出，这本身不代表命令失败。

## 提交和推送分别做什么

提交是在本地历史里建立一个新记录。推送是把本地的相应提交发送到远端仓库。没有推送，本机历史仍然有价值；但本机故障时，未另行备份的内容可能无法恢复。

忽略规则只影响哪些未跟踪文件会被默认考虑加入。把文件名写进 `.gitignore`，不会自动停止跟踪已经入库的文件，更不会抹除历史里的内容。因此样例配置只留占位值，真正的本地配置和临时数据库需要妥善处理。

本讲主要先学观察。涉及丢弃更改、重写历史的命令，不在刚入门时靠背诵尝试。先在独立教学仓库理解，再处理实际工作。

## 怎样读 Agent 的一次差异

先看行为目标，再看文件列表，最后沿一个功能追变化。比如“禁止覆盖已有报告”应能在写入前的判断、文件创建方式和错误测试里找到对应。若差异顺带换了路由框架、调整数据库和删除测试，需要分别问它们为何属于本次目标。

差异里删除一段校验，也许让正常路径更短，却可能扩大可接受输入。审查时不能用“减少代码行数”代替行为判断。

一次修改最好能用一句话说明目的。不同目的混在一起，会使后续定位和回退更难；但也不是每改一行都必须提交一次，要看这些变化是否共同形成一个可验证行为。

## 一个与你仓库直接相关的例子

有时子目录里又存在独立 Git 仓库，外层提交可能只记录内层仓库的某个提交引用。它不会像普通文件夹一样自动把所有文件内容收进外层仓库。正式子模块还需要路径与来源配置。

你当前第一题就出现了这种引用，而主仓库缺少可用来源。GitHub 上看不到里面的 `Demo.go`，不能据此认定你本地没写代码。这个问题要先检查目录和 Git 状态，再选择保留独立仓库还是作为普通目录管理。操作前保留完整副本，不能直接删掉你的练习历史。

## 今天留下什么证据

工作日找一份小的改动差异，说明一处新增和一处删除分别改变什么。周末在独立练习仓库改两份文件，只暂存其中一份，观察三个状态区。真正提交或推送之前，先明确自己正在操作哪个仓库及分支。

## 原有九轮怎样使用

以下保留原有练习。源码题涉及旧版 NetMon 定位时，要核对当前代码；Go/C#尚不熟时先口述同一行为，之后再编码。一次做当前一小步，不要求一天完成九轮。

## 九轮练习

1. **读与预测**：纸面画出A→暂存B→工作区C，分别写三个状态区中的内容。
2. **正常变式**：两个教学文件，一个修改日志格式，一个修正拼写；说明如何只把前一个改动放进一次提交。先口述，不在生产仓库操作。
3. **边界**：文件已被Git跟踪，再写进`.gitignore`，它会怎样？写下预测，再查官方说明。
4. **排错**：发现提交漏了最后一处修改，先用哪些只读命令定位？避免立刻重置或强推。
5. **独立完成**：为自己的一个小修改写四句话提交说明；列出应该包含和不应包含的文件。
6. **源码**：只读查看 NetMon Runtime启动文件及最近相关提交，回答为什么源码和启动配置需要匹配版本。
7. **C#对照**：比较Go编译产生的程序与C#的`bin/obj`目录，说明共同维护的应该是什么；具体例外以仓库约定为准。
8. **间隔复习**：完成第05讲后，再解释“保存、暂存、提交、推送”，每个用一句话。
9. **迁移**：假设Agent新增三份文档和一个日志文件，逐个判断是否应该提交，并给出理由。第三方内容额外核对许可。

## 核对思路

A/B/C例子的普通提交采用B。检查漏改时先看状态和两类差异；不要把“撤销所有修改”当作恢复某一文件的默认方式。提交说明应描述行为和证据。独立的Git练习可另建专用沙盒，本资料没有在你现有仓库创建提交或更改分支。

原讲义还介绍Git内部对象、分支演示工具和更细的工程习惯。先把状态区弄清，再沿着一个提交认识内容对象、目录树和父提交，不必第一天读完整个Git实现。
