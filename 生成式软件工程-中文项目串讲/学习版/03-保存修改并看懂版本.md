# 第03讲：保存修改并看懂版本

对应原课：版本管理①。[在线原文](https://jyywiki.cn/GSE/2026/lect3.md) · [本地原文](../原始讲义/正文文本/lect3.md)

你已经问过“怎样提交到仓库”。这一讲先把保存与提交讲清楚；本资料生成过程没有替你执行暂存、提交或推送。

## 为什么编辑器保存还不够

你今天把日志改好了，明天又改坏。如果只有当前文件，就很难准确找回昨天的代码、当时的配置及为什么这样改。复制一堆“最终版”能临时保留内容，却难以记录这些版本之间的关系。

Git为项目保存有关系的快照。一次提交记录选定文件的状态及说明、父提交等信息。逻辑上是一个项目状态，不意味着每次都把所有文件重新复制一遍。历史是否存在，也取决于相关内容有没有进入提交，不能指望Git恢复从未保存过的任意内容。

## 三个状态区，逐个看

工作区是你正在编辑的文件。暂存区是准备放进下一次普通提交的内容。提交历史是已经记录的快照。

假设文件最初写A，你改成B并暂存，随后又改成C。现在工作区是C，暂存区是B；普通提交会记录B，C仍是未暂存的修改。这不是提交丢数据，而是你要分清“当前文件”和“下一次提交准备采用的内容”。

`git diff`主要查看工作区与暂存区之间的变化；`git diff --cached`查看暂存区与当前提交之间的变化；`git status --short`给出状态概览。初次使用请一次只看一个文件，并先预测差异会在哪里出现。

## 先做只读观察

下面的命令在PowerShell中执行，不是Go代码。第一行切换目录，后面查看当前仓库状态和历史，不改变提交。

```powershell
Set-Location 'D:\GoPractice'
git status --short
git diff --stat
git log -5 --oneline
```

`-5`表示最多显示五条提交；`--oneline`让每条简短显示。它们是命令行选项，不是Go中的减法。如果Git提示所有权或访问权限问题，先核对当前账号和目录来源；不要为了读日志就随意更改所有目录的全局信任设置。

当你决定提交一个具体文件，才会用`git add`将它当前内容放入暂存区，再查看暂存差异，最后`git commit`。推送是把本地提交发送到远程仓库，属于下一步。Git本身与GitHub托管平台不是同一个东西；本地记录版本不需要先推送。

不要对尚未检查的整个目录盲目执行`git add -A`。尤其你现在的学习目录有自己的作业、示例和资料，应逐项判断是否要纳入。

## 什么值得保存到仓库

源码、需求、必要的测试、依赖版本和构建说明通常值得保存，因为它们帮助别人重建和理解程序。运行日志、数据库实例、密钥和临时编译文件通常不属于共享源码。

这是按用途判断，不是看到自动生成的文件就一律删除。例如依赖锁文件虽然由工具生成，却可能用于固定版本。`.gitignore`负责忽略尚未跟踪的匹配路径，不会自动删除历史里的密钥，也不会让已经跟踪的文件立即退出管理。

本次课程资料包含第三方讲义，保留作者和许可；如果以后推送，你需要知道这些资料有自己的CC BY-NC许可，不会因根目录使用另一种许可证就自动改变。

## 读懂一次修改比记命令更重要

可以用四句话描述一个提交：原来哪里不对；这次改变了什么行为；怎样检查；哪些情况还没验证。比如“未知路径没有完成日志；增加兜底路径记录；已用本机404请求核对；尚未验证并发请求”。这比“优化代码”更容易让未来的你定位问题。

NetMon可以作为只读练习对象：先选一个熟悉的函数，查看当前内容，再查看相关历史。旧提交表达当时状态，不自动代表当前事实。看到过去修过某个问题，也要确认当前代码是否仍保留修复。

## 九轮练习

1. **读与预测**：纸面画出A→暂存B→工作区C，分别写三个状态区中的内容。
2. **正常变式**：两个教学文件，一个修改日志格式，一个修正拼写；说明如何只把前一个改动放进一次提交。先口述，不在生产仓库操作。
3. **边界**：文件已被Git跟踪，再写进`.gitignore`，它会怎样？写下预测，再查官方说明。
4. **排错**：发现提交漏了最后一处修改，先用哪些只读命令定位？避免立刻重置或强推。
5. **独立完成**：为自己的一个小修改写四句话提交说明；列出应该包含和不应包含的文件。
6. **源码**：只读查看 NetMon Runtime启动文件及最近相关提交，回答为什么源码和启动配置需要匹配版本。
7. **C#对照**：比较Go编译产生的程序与C#的`bin/obj`目录，说明共同维护的应该是什么；具体例外以仓库约定为准。
8. **间隔复习**：完成第05讲后，再解释“保存、暂存、提交、推送”，每个用一句话。
9. **迁移**：假设Agent新增三份文档和一个日志文件，逐个判断是否应该提交，并给出理由。第三方内容额外核对许可。

## 核对思路

A/B/C例子的普通提交采用B。检查漏改时先看状态和两类差异；不要把“撤销所有修改”当作恢复某一文件的默认方式。提交说明应描述行为和证据。独立的Git练习可另建专用沙盒，本资料没有在你现有仓库创建提交或更改分支。

原讲义还介绍Git内部对象、分支演示工具和更细的工程习惯。先把状态区弄清，再沿着一个提交认识内容对象、目录树和父提交，不必第一天读完整个Git实现。
