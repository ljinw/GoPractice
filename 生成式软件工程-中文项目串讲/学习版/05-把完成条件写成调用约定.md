## 一次函数调用，是把什么交给谁

先把函数想成一段有名字、可以重复使用的处理步骤。调用者提供输入，函数执行后可能交回结果，也可能修改文件、发送请求或打印文字。读代码时要分别找到这些动作。

我们先只处理名字。下面是完整教学程序，内容只使用标准库；它与后面假模型实验分开运行。程序中 `cleanName` 是我们自己起的函数名。

```go
package main

import (
    "fmt"
    "strings"
)

func cleanName(raw string) (string, error) {
    name := strings.TrimSpace(raw)
    if name == "" {
        return "", fmt.Errorf("名字不能为空")
    }
    return name, nil
}

func main() {
    name, err := cleanName("  notes.md  ")
    if err != nil {
        fmt.Println(err)
        return
    }
    fmt.Println(name)
}
```

保存为独立目录中的 `main.go`，使用本机 Go 执行 `go run main.go`。预期输出 `notes.md`。本次修订中的代码块是教学解释；可执行专题样例的实际验证记录另见样例目录，不能把这里的预期自动当成你本机已经运行。

## 把第一行签名拆开

`func` 声明函数。`cleanName` 是名字。`raw string` 表示接收一个字符串参数，函数内部叫它 raw。后面的 `(string, error)` 表示返回两个值，第一个是整理后的字符串，第二个说明是否出现错误。

调用时，`"  notes.md  "` 传给 raw；函数执行后，两个返回值分别交给 main 里的 name 和 err。它们名字相同不是语言要求。你可以写 `result, problem := cleanName(...)`，关键是类型和返回顺序对应。

`:=` 在这里声明新变量并赋初值。`name == ""` 比较是否为空。`return` 结束当前函数，并把后面的值交给调用者。`nil` 在这个位置表示没有返回错误。

## 顺着两条路径各走一次

正常输入时，TrimSpace 产生新字符串，空值判断不成立，函数返回 `notes.md` 和 nil。main 检查 err 后打印名字。

纯空白输入时，整理结果是空字符串，函数返回空字符串和错误。main 进入错误分支，打印后结束。若 main 不检查 err，继续把空字符串当作文件名，就把失败当成了正常数据。

整理字符串成功不等于文件存在，也不等于用户有权读取。一个函数只承诺自己真正检查的事情。后续文件访问还要另做检查。

## 返回值、HTTP响应和日志为什么不能混淆

| 代码动作 | 谁接收它 | 影响什么 |
|---|---|---|
| `return name, nil` | Go 调用者 | 当前函数调用的结果 |
| `fmt.Println(name)` | 标准输出 | 通常是终端文字 |
| `fmt.Fprintln(w, name)` | w 对应的写入目标 | HTTP处理中通常是响应正文 |
| `log.Print(err)` | 日志输出目标 | 诊断记录 |

这里的 w 是变量名，不是 Go 关键字。处理 HTTP 时，它的类型决定了能调用什么方法。向 w 写内容，与给普通调用者 return 字符串，是两种不同的数据传递方式。

函数没有普通返回值，也可以写文件或发出请求。这些影响函数外部世界的动作叫副作用。以后讨论重试时，要先找副作用在哪里，才能判断是否可以重复执行。

## 接口为什么会要求某一种函数形状

调用者需要提前知道怎样提供参数、怎样接收结果。HTTP 框架要把请求和响应写入器交给处理函数，因此它要求对应参数形状。你多加一个返回值，框架就未必接受，因为双方约定不一致。

这和协议字段不匹配相似：两边都“有数据”还不够，要对字段、顺序和含义达成一致。后面的 Eino 与 DSH 也一样，工具输入、返回类型与失败规则都属于约定。

C# 通常用异常或结果对象等方式表达失败；不能仅把 Go 的 `(结果, error)` 换一套符号就认定行为相同。先比较空输入应怎样处理，再比较语法。

## 原练习的第二个例子：状态码怎样变成标签

上面的cleanName用于先理解输入、两个返回值和错误。下面保留原九轮对应的状态码例子，两者分别放在独立目录运行，避免重复main。

```go
package main

import "fmt"

func statusLabel(status int) string {
    if status >= 200 && status < 300 {
        return "成功类响应"
    }
    return "其他响应"
}

func main() {
    label := statusLabel(202)
    fmt.Println(label)
}
```

保存为另一目录中的main.go，运行go run main.go。status是参数名，int是类型；括号后的string声明一个返回值。202进入函数后满足两个比较条件，结果交给label，再被打印。200、404、0、999留给下面的预测练习。这个函数只贴教学标签，不校验所有HTTP状态码，也不发送HTTP响应。

## 函数值和调用结果：原练习第4轮在问什么

以下是HTTP处理函数的签名示意，需在导入net/http的上下文中理解，不是独立运行程序：

```go
func httphealth(w http.ResponseWriter, r *http.Request) {
    w.WriteHeader(http.StatusOK)
}
```

`httphealth`表示函数这个值，可以在匹配签名时登记给路由器，等待请求到来后再执行。`httphealth(w, r)`表示现在调用它；该函数没有普通返回值，因此不能把这次调用当成一个返回处理器的表达式。原练习中的省略号是说明“这里需要参数”，不是让你原样粘贴运行。

路由登记中的handler需要符合约定的函数值；HTTP请求到来后由框架提供w和r。w用于写响应，r提供请求信息，名字不是固定关键字。

## 对应的C#方法：原练习第7轮的对象

下面放在类或适当程序上下文中，属于方法片段；本次未编译运行C#。

```csharp
static string StatusLabel(int status)
{
    if (status >= 200 && status < 300)
        return "成功类响应";
    return "其他响应";
}
```

C#把返回类型string写在方法名前，参数写“类型 名字”；Go的返回类型在参数列表后，参数写“名字 类型”。两者在这个例子里接收整数并返回字符串。C#的void表达不返回普通值；ASP.NET的IResult等结果对象又是另一种由框架组织HTTP响应的方式。先比较业务行为，再比较具体写法。

## 九轮练习

1. **读与预测**：不运行，写出示例在200、202、404下的结果，标注参数与返回值。
2. **正常变式**：只改教学标签文字，观察调用者是否需要变化，再增加一个调用位置。
3. **边界**：输入0、999时原函数会怎样？先决定业务要求，再决定是否增加错误返回；不要只为凑代码加入分支。
4. **排错**：解释把`httphealth(...)`放到需要处理函数值的位置为什么可能报错。分别指出“现在执行”和“以后执行”。
5. **独立完成**：为“读取某份报告”的函数写意图注释，包含输入、成功、失败和副作用；暂不写实现。
6. **源码**：在当前Go安装中通过编辑器跳转`HandleFunc`，记录Go版本与完整签名，只追到直接注册调用。版本不同，匹配行为要另核对。
7. **C#对照**：逐项标记上述方法的返回类型、参数名、参数类型；说明不能把C#异常与Go的error变量直接视为相同语法。
8. **间隔复习**：完成第07讲后，合上资料重新解释“函数值”和“调用结果”。
9. **迁移**：读NetMon创建任务处理函数，区分它的普通返回、HTTP202响应、后台任务效果和日志记录。

## 核对思路

200和202属于示例的成功分支；404走其他分支。0与999也走其他分支，说明当前合同没有做状态范围校验。注册处理函数时要交符合签名的函数值。一个没有普通返回值的函数仍然可以产生HTTP响应，这不矛盾。
