# 中文术语与项目定位

遇到词再查，不要求预先背诵。中文解释用于当前课程语境；同一个英文词在别处可能有不同含义。

| 英文 | 本资料采用的中文 | 用你的项目理解 |
|---|---|---|
| Intent | 真正想解决的问题 | 想查清接口异常，而不只是得到一段回答 |
| Spec / Specification | 可检查的要求 | 哪台设备、哪个时间窗、哪些输出和失败行为 |
| Implementation | 实现 | 处理函数、业务规则与工具调用的实际代码 |
| Contract | 调用约定 | 参数、返回、失败、副作用及权限要求 |
| Prompt | 给模型的任务说明 | 告诉它分析什么、遵守什么输出要求 |
| Context | 模型当时看到的材料 | 请求、规则、历史、Skill、工具结果 |
| Context Engineering | 组织模型所需资料 | 决定给什么、给多少、怎样标明来源 |
| Token | 模型处理文本的计量单位 | 用来理解容量与消耗，不等于一个汉字 |
| Agent | 围绕目标组织模型和工具的系统 | 接收网络任务、调用获准能力、返回结果 |
| Agent Loop | 执行循环 | 请求模型、处理动作、收集结果、决定继续或停止 |
| Harness | 运行底座 | 工具、权限、上下文、状态、反馈和恢复等配套机制 |
| Runtime | 运行时服务或执行环境 | 在NetMon中有专门的Go/Eino Runtime服务；范围不等于整个Harness |
| Tool | 工具 | 具有明确输入输出与权限边界的实际能力 |
| Skill | 可复用的方法与资料 | 当前任务需要的领域说明和操作知识，不自动授予工具权限 |
| MCP | 模型上下文协议 | 组织工具等能力的协议；采用协议不等于已经完成身份隔离 |
| Guard | 执行前后的约束检查 | 检查敏感信息、范围、动作或输出 |
| Schema | 数据形状与约束说明 | 必须字段、类型及结构；不单独证明事实正确 |
| State Machine | 状态与允许变化的规则 | 待执行、执行中、失败、等待用户等状态怎样转换 |
| DAG | 无环依赖图 | 后一步依赖哪些前一步结果；不是所有图都允许循环 |
| Idempotency | 重复请求不额外产生业务效果 | 同一个提交请求重试时不重复建立任务 |
| Lease | 有时限的处理资格 | 工作进程在约定期限内领取任务，提交仍需核对资格 |
| Review | 复核 | 检查证据和候选结果，不因叫Reviewer就自动正确 |
| Eval / Evaluation | 效果评估 | 按事先标准比较结果质量与成本 |
| Traceability | 能追查要求、代码与证据的关系 | 从报告结论找到事实、规则与任务 |
| Observability | 通过外部信号理解系统状态 | 从日志、指标和调用记录定位失败 |
| CI | 持续集成与自动检查 | 变更后检查组合是否仍符合要求 |
| CD | 持续交付或持续部署 | 前者保持可发布，后者进一步自动发布，按具体语境区分 |
| MVP | 用于验证核心假设的最小可用版本 | 先完成一份可核对的报告，不先搭齐所有中间件 |
| Event Sourcing | 用业务事件重建状态的设计 | 保存发生了什么，并按明确规则推导结果 |
| CQRS | 命令与查询职责分离 | 写入时作业务决定，查询时组织展示，不必立即拆库 |
| DDD | 让业务概念决定模型与边界 | 分清资产、巡检事实、分析叙述和通知 |
| Abstraction | 通过明确约定隐藏暂时不用展开的细节 | 调用读取报告能力，不必每次理解连接实现 |
| Technical Debt | 让后续修改付出额外代价的设计负担 | 旧假设失效或规则复制，使新需求越来越难改 |
| Artifact | 交付或开发过程中产生的对象 | 源码、需求、测试、构建结果；是否入库按用途判断 |
| Commit / Branch / Merge | 提交／分支／合并 | 保存状态／不同演进路线／整合修改 |
| Rebase / Worktree | 重放到新起点／多个工作目录 | 管理历史与工作区的机制，不自动隔离数据库和端口 |

## 两种“助手”别混淆

你用编程助手开发NetMon，这是开发过程。NetMon自身面向运维人员提供网络分析Agent，这是产品运行过程。二者都涉及上下文、工具、权限和反馈，但任务对象不同。开发助手能改代码，不代表产品Agent应该允许改设备配置。
