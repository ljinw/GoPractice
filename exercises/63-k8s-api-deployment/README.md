## 业务为什么需要它

一个实例退出后，系统需要有明确的替代和流量接管行为。

## 这次做成什么

在教学集群部署两份无状态 API 并验证替代。

## 具体需求

使用 go-practice 命名空间和固定镜像，配置 Deployment、Service、资源请求、探针、终止预算及必要配置引用；先通过端口转发验证，不急于安装入口控制器。有状态依赖沿用已验证教学环境并核对连接预算，不能给两个 Pod 各建独立事实库。

## 输入与结果

两个API实例→删除其中一个教学Pod→其他实例继续可用、替代Pod就绪。

## 今天从这里动手

1. 先确认当前集群确为教学环境并记录命名空间。
2. 将讲义模板替换为本项目真实镜像/探针，再建立 Service。
3. 观察删除一份实例前后的请求、Endpoints和替代过程。

## 怎样算完成

- [ ] 两个实例读取同一套授权的任务事实，Service选择器正确。
- [ ] 实例替换后业务可完成，幂等和权限仍成立。
- [ ] readiness失败的实例退出正常流量，配置与密钥不写死进镜像。

## 实验记录与边界
