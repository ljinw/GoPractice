## 业务为什么需要它

不同检查类型的报告正文结构不同，想比较文档模型能否更方便读取整份报告。

## 这次做成什么

在对照实验中替换报告正文仓储，保持原接口行为。

## 具体需求

通过同一个报告仓储合同选择 MongoDB 实现；同一运行配置只选择一个正文权威来源。报告含 tenant_id、job_id、schema_version 和事实引用，保持不可变快照。若关系库保留索引，采用可恢复的写入/对账流程，不宣称跨库自动原子；失败时不能返回成功正文。

## 输入与结果

原 GET /inspection-jobs/{id}/report 的结果与权限不变，正文从指定 MongoDB 仓储读取。

## 今天从这里动手

1. 先记录原报告仓储的输入输出测试。
2. 用单份合成报告设计嵌入字段、版本及唯一约束。
3. 替换仓储配置并注入写入故障，复跑原合同测试。

## 怎样算完成

- [ ] 正常报告的字段和事实引用与原实现一致。
- [ ] 同 job_id 重试不生成两份有效报告，越权读取失败。
- [ ] 正文或索引写入故障可观察和恢复，不出现伪造的成功状态。
