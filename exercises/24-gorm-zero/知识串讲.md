## 与本题相连的原理和工程做法

### 指针、方法、接口：分三次理解

`&device` 取得指向变量的指针；类型中的 `*Device` 表示指针类型；表达式中的 `*p` 取得它指向的值。Go 的参数仍然按值传递，传指针也是复制指针值；多个指针可以指向同一对象。

方法是在函数名前多写一个接收者，例如 `func (d *Device) Rename(name string)`。d 是本次方法调用使用的对象。`d.Rename("new")` 把这个对象与显式参数一起交给方法。指针接收者常用于修改对象或避免复制较大的对象，但它不自动保证并发安全。

接口描述“需要哪些方法”。只要某个类型的方法集合满足接口，它就实现该接口，不需要 implements 关键字。先认识 io.Writer、http.Handler 等真实用法，等需要替换数据库实现或假模型时再定义自己的小接口。

这些语法的准确规则可查 [Go 语言规范](https://go.dev/ref/spec)，命名、方法和错误处理习惯可对照 [Effective Go](https://go.dev/doc/effective_go)。

### ORM 不会替你决定数据库正确性

GORM 让结构体与查询更方便，但你仍要看生成的 SQL、WHERE、事务和受影响行数。传统 API 中用结构体 Updates 默认忽略零值；想把 enabled 改成 false，需明确选择字段或使用适合的 map 更新，而不能只看对象里 false 已赋值。[GORM 更新合同](https://gorm.io/docs/update.html)。

N+1 查询是查 20 份报告后再为每份报告单独查设备。可以批量查关联、预加载或按需求 JOIN，但 JOIN 也可能扩大行数，导致分页重复和计数错误。先决定页面要哪些字段，再选择查询策略。
