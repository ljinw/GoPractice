## 与本题相连的原理和工程做法

### Agent 工具、流式输出与成本

Tool 是可以被调用的能力，应有输入校验、最小权限、超时、调用次数与审计。读到的文档或设备输出可能包含诱导性文字，它们属于数据，不能提升为操作授权。初始工具只做获准范围内的只读查询。

SSE 持续输出进度或文本，但任务结果仍应持久化。浏览器断线后能按 job_id 查询状态；不能只在内存流里保存唯一结果。Nginx 缓冲、代理读超时、客户端取消都可能影响体验，[第 58 题讲义](../58-nginx-project-gateway/知识串讲.md)。

模型慢或限额不足时要排队/降级，控制总 token、并发、最大步骤数和成本。日志记录供应商、模型配置版本、耗时、用量与错误分类，避免原样收集敏感提示词。质量评估使用固定事实集：是否引用正确、是否承认缺失、是否越权、是否杜撰。


### 认证、授权、审计是三件事

认证回答“你是谁”；授权回答“这个资源你能不能读或改”；审计回答“谁在什么时候对什么做了什么，结果怎样”。读取 /inspection-jobs/123/report 时只检查 token 合法还不够，还要检查 report 属于当前用户或租户。

租户不能由客户端随意填一个请求头就变可信。资源查询带上可信租户范围，缓存 Key 和消息任务也要保持范围；AI 检索同样受限。服务之间的身份与终端用户身份要区分，不能让“内部服务已认证”自动变成读取任何用户数据的权限。

日志中的 user_id、tenant_id 是审计线索，不是证明访问获准的机制。敏感正文、密码、token 不应进入普通日志；审计记录要有访问控制和保留策略。
