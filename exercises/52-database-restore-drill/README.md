## 业务为什么需要它

数据库文件损坏或误操作后，运维需要知道能恢复到哪一刻。

## 这次做成什么

完成一次有明确恢复点的隔离恢复演练。

## 具体需求

为假设备、任务和报告建立一致备份；若正文在文件中，同步建立对应清单。恢复到新数据库/新目录，不覆盖原环境；核对恢复点前后的记录、报告索引与正文。记录恢复耗时和缺失范围，真实库不在本题范围。

## 输入与结果

备份前写 task-a，备份后写 task-b；恢复旧备份后应有 a、不承诺有 b。

## 今天从这里动手

1. 先列要保留的数据及明确的恢复目标。
2. 按所选数据库的一致备份方法备份，随后追加标记数据。
3. 恢复到新位置，跑创建任务与查询报告的最小回归。

## 怎样算完成

- [ ] 备份能在另一套隔离环境恢复并被应用读取。
- [ ] 恢复点和缺失范围有证据，报告索引没有虚假的成功正文。
- [ ] 记录恢复时间与操作步骤，原练习数据库未被覆盖。
