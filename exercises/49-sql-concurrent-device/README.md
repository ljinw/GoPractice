## 业务为什么需要它

两位运维人员同时打开同一台设备，后提交的人不能覆盖自己没看过的新版本。

## 这次做成什么

给设备更新增加版本冲突检测。

## 具体需求

在隔离 MySQL/InnoDB 教学库复用设备模型，新增 version；更新携带读取时的 version，按 tenant_id、id、version 条件更新并自增。匹配一行成功；旧版本返回 409 且数据不变。不存在或越权沿用原权限策略。SQLite 阶段已完成的逻辑保留为前置成果，本实验不把 MySQL 行锁语法套到 SQLite。

## 输入与结果

两客户端都读取 version=1；A 改名成功为 version=2；B 持旧版本修改 → 409。

## 今天从这里动手

1. 先用两个连接复现读后覆盖，并记录先后顺序。
2. 阅读本题讲义，先观察锁等待，再把示例条件更新接到已有设备仓储。
3. 重复并发请求并检查受影响行数、版本与 HTTP 响应。

## 怎样算完成

- [ ] 两个相同版本的并发更新最多一个成功，最终内容与成功请求一致。
- [ ] 旧版本重试不覆盖新值；重新读取后才能再次修改。
- [ ] 另一租户同编号设备不受影响，原设备查询与启停回归通过。
