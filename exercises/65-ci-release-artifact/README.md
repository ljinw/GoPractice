# 65 · 让一次代码改动产出可追溯的发布包

项目：设备巡检与 AI 报告助手。前置：[48 · 交付一个能演示和复现的巡检助手](../48-business-e2e/README.md)、[62 · 重建容器后巡检数据仍能使用](../62-container-persistent-project/README.md)。

## 先学再练

先读同目录的 [知识串讲](知识串讲.md)，再动手完成本题。这里继续修改已有项目的相关模块，不新建一套脱离业务的演示系统。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

交给运维的版本必须知道来自哪里、经过哪些检查。

## 这次做成什么

建立同一项目的可重复构建与检查入口。

## 具体需求

本地流水线或选择的一套CI依次执行相关检查、单元/集成验证、构建镜像并输出代码版本、镜像标识与结果；失败即停止产物晋级。先使用本地或隔离仓库，不上传真实秘密、不自动部署生产。说明测试跳过与外部环境边界。

## 输入与结果

一处故意引入的测试失败阻止发布；修复后生成与源版本对应的产物清单。

## 今天从这里动手

1. 先整理现有项目启动与测试命令，不硬套不存在的目录。
2. 把检查与构建串联并记录失败停止位置。
3. 故意破坏一个业务断言，再修复并对照产物结果。

## 怎样算完成

- [ ] 故意失败会阻断后续晋级，不能仍标成功。
- [ ] 产物有可追溯版本与验证结果，测试和部署使用同一产物身份。
- [ ] 配置/秘密不进入镜像和公开日志，重新执行能得到可解释结果。

## 实验记录与边界

在本题目录记录实际环境版本、输入、预期、结果和证据路径；未运行的检查保持未勾选。只使用隔离教学数据、本机/本地教学服务、假通知和假模型。真实生产上线、真实设备及付费调用不在本题授权内。
