## 这次做成什么

读取客户端提交的 JSON，校验设备名称后原样返回。

## 具体需求

新增 POST /device-preview，读取 {"name":"sw-core","ip":"192.0.2.10"}。name 去除两端空白后不能为空；成功返回 200 和整理后的同结构 JSON。空正文、坏 JSON、顶层 null、缺少 name 或空白 name 返回 400，正文 {"error":"invalid request"}。这一题不保存资料，IP 格式留到第 07 题。

## 输入与结果

```text
POST /device-preview
{"name":" sw-core ","ip":"192.0.2.10"}
→ 200，{"name":"sw-core","ip":"192.0.2.10"}
```

## 怎样算完成

- [ ] 正常 JSON 返回整理后的 name 和原 ip。
- [ ] 空正文、{、null、{}、空白 name：均为 400。
- [ ] GET /device-preview：405；失败后再次发正常请求仍可成功。

## 本题常用写法（遇到再看）

```go
err := json.NewDecoder(r.Body).Decode(&device)
```

- 【常见命名】`req`、`request` 常指解析后的业务输入；`r` 常指原始 HTTP 请求。名字可改，但别把两层对象混淆。
- 【语法与库合同】`&device` 把变量的地址交给 Decode，供它填入字段。参数类型需要指针时才这样传。
- 【常见错误处理】紧接着检查 `if err != nil`；`err` 是普通变量名，nil 在这里表示没有错误。
- 【控制流程】写出错误响应后通常接 `return`，避免继续执行成功分支。return 结束当前函数；HTTP 响应由 w 写出。
