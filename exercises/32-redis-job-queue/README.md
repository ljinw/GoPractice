# 32 · 把耗时巡检交给后台处理

阶段：Redis Streams。前置：第 31 题。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

提交接口应尽快返回，耗时工作由后台执行。

## 这次做成什么

使用持久化事件把任务交给 worker。

## 具体需求

创建任务与 outbox 事件同一数据库事务；发布器将事件 XADD 到 Redis Stream 后标记已发布。worker 用消费组读取，调用现有 RunJob；业务结果持久化后再 XACK。重复消息凭 job_id 和任务状态去重。Redis 断开时，已入库任务保持 queued，发布器恢复后补发。崩溃后的 running 恢复在第 33 题完成。

## 输入与结果

```text
POST 立即 202；后台消费后 GET 状态变 succeeded，报告可查
```

## 怎样算完成

- [ ] 有意让执行耗时 2 秒，提交接口不等待执行结束。
- [ ] Redis 暂停时任务和 outbox 均在；恢复后最终执行。
- [ ] 发布成功但标记前崩溃造成重复投递，仍只有一份报告。

## 本题常用写法（遇到再看）

【常见名字】producer/publisher、consumer/worker、ACK、outbox。【合同】至少一次投递可能重复，不宣称天然只执行一次。
