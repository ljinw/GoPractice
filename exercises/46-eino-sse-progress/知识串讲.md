### 2. 这次新增什么

select 等待多个事件。

下面是局部片段，不是可单独运行的完整程序。放置位置：**返回 error 的流式处理函数片段**。代码中的业务对象或函数需要来自你前面已完成的程序；暂时没有时，先用假值练这个语法。

```go
select {
case <-ctx.Done():
    return ctx.Err()
case event, ok := <-events:
    if !ok {
        return nil
    }
    return sendEvent(event)
}
```

### 3. 顺着代码读一遍

select 等待可执行分支；ctx.Done 通知取消；接收 channel 的 ok 为 false 表示已关闭。这里只处理一次事件。

### 4. 接到当前模块

完整 SSE 会循环接收、输出和刷新；循环中仍必须保留取消和 channel 关闭出口。sendEvent 负责当前事件的写入错误。

### 5. 跟写、改一点、说回来

用假事件通道分别制造事件、关闭、取消三种情况，确认函数都能结束或返回正确结果。

## 与本题相连的原理和工程做法

### Agent 工具、流式输出与成本

Tool 是可以被调用的能力，应有输入校验、最小权限、超时、调用次数与审计。读到的文档或设备输出可能包含诱导性文字，它们属于数据，不能提升为操作授权。初始工具只做获准范围内的只读查询。

SSE 持续输出进度或文本，但任务结果仍应持久化。浏览器断线后能按 job_id 查询状态；不能只在内存流里保存唯一结果。Nginx 缓冲、代理读超时、客户端取消都可能影响体验，[第 58 题讲义](../58-nginx-project-gateway/知识串讲.md)。

模型慢或限额不足时要排队/降级，控制总 token、并发、最大步骤数和成本。日志记录供应商、模型配置版本、耗时、用量与错误分类，避免原样收集敏感提示词。质量评估使用固定事实集：是否引用正确、是否承认缺失、是否越权、是否杜撰。


### SSE、请求体与配置更新

流式接口可能需要关闭对应 location 的响应缓冲，并设置与心跳间隔匹配的读超时。proxy_read_timeout 是两次读取之间的间隔约束，不是简单的整个响应总时长。普通接口与 SSE 分开设置，不全局拉长所有超时。

上传大小、请求头大小、客户端慢发送同样需要限制。Nginx 限流与应用限流各有位置，最终仍要保护数据库和模型等共享资源。

更新配置先做语法校验，再 reload，再检查入口请求、错误日志和新 worker 状态。reload 支持平滑替换进程，但配置正确不等于业务路由正确。[Nginx 入门与配置重载](https://nginx.org/en/docs/beginners_guide.html)。
