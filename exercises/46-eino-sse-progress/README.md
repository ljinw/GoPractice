## 业务为什么需要它

耗时分析需要进度反馈，连接断开也要释放资源。

## 这次做成什么

通过 SSE 发送分析阶段事件和最终结果编号。

## 具体需求

对一次新分析请求建立 SSE，沿用同一 AnalysisService；只发送阶段进度、done(analysis_id) 或 error，先不把未经校验的模型文本当最终答案展示。先认证再建立流；客户端断开传递取消，停止模型/工具等待。输出每个事件后及时 flush，终态后关闭。

## 输入与结果

```text
progress: loading → progress: analyzing → done: analysis_id
```

## 怎样算完成

- [ ] 用户在分析结束前能收到至少一个进度事件。
- [ ] 模型或校验失败发送 error，不发送虚假的 done。
- [ ] 客户端断开后调用结束、资源释放；其他用户不能订阅该报告分析。

## 本题常用写法（遇到再看）

【协议】Content-Type 为 text/event-stream，事件以空行分隔。【常见写法】Context 取消、Flush；进度事件不等于最终业务结果。
