# 34 · 把报告就绪消息送到本机接收器

阶段：报告通知。前置：第 33 题。

## 业务为什么需要它

用户不应一直刷新才能知道报告已经生成。

## 这次做成什么

可靠投递一条报告就绪通知并可查发送结果。

## 具体需求

报告完成时同事务写 report.ready 事件；投递器向固定配置的本机 webhook 发送 report_id、摘要和 event_id，设置超时。记录每次投递及最终状态，失败最多重试 3 次。接收器用 event_id 去重。只向本机 mock 接收器发消息，不连接钉钉或邮箱。

## 输入与结果

```text
报告就绪 → 本机接收器收到通知 → 发送记录显示 delivered
```

## 怎样算完成

- [ ] 正常返回 2xx 时记录投递成功。
- [ ] 模拟接收端已接收但响应丢失，重试后接收端只有一条业务记录。
- [ ] 连续超时最终 failed，报告仍可查询，日志不伪装通知成功。

## 本题常用写法（遇到再看）

【业务区分】报告结果和通知投递状态独立。【常用写法】eventID 用于接收去重，requestID 用于追查一次发送。
