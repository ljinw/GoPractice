# 37 · 让远程调用有身份与截止时间

阶段：服务调用治理。前置：第 36 题。

## 先学再练：本题串讲

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

跨进程调用会失败或变慢，也需要识别调用方。

## 这次做成什么

给 inventory 调用加上有限等待与独立服务凭据。

## 具体需求

由环境配置独立内部 Token，与用户 Token 分开；服务端中间件校验，失败拒绝。客户端把父 Context 传给 gRPC，并设置最多 1 秒期限；上游取消时停止等待。超时映射为外部 504，不可用为 503，不创建半份巡检任务。创建操作不做无条件自动重试。

## 输入与结果

```text
inventory 模拟慢 5 秒 → 调用方约 1 秒失败，数据库没有新任务
```

## 怎样算完成

- [ ] 正确内部凭据可调用，缺失或错误凭据被拒绝。
- [ ] 超时与客户端取消能结束调用，未留下 queued 半成品。
- [ ] 用户 Token 不被当成内部服务凭据，也不出现在普通日志。

## 本题常用写法（遇到再看）

【常用写法】ctx、deadline、metadata、interceptor/middleware。【合同】超时后客户端不知道结果时，写操作需要幂等设计才能安全重试。
