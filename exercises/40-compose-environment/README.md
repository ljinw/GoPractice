# 40 · 让本机练习环境可重复启动

阶段：Docker Compose。前置：第 39 题。

打开本目录的 [知识串讲](知识串讲.md)，先学这题需要的语法、原理和常用写法，再回来实现下面的业务需求。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

别人或未来的自己应该能按说明重现系统。

## 这次做成什么

用配置启动本地服务与必要依赖。

## 具体需求

编写 Compose 描述 inventory、inspection/API、worker、本机 webhook、Redis、etcd；按实际代码入口选择容器，避免重复启动相同调度器。宿主机映射只绑定 127.0.0.1；容器内部按服务名通信。为各自数据配置独立卷，配置 healthcheck 和故障重连。版本使用明确标签或摘要；秘密放忽略的本地环境文件。

## 输入与结果

```text
启动 → 完成一次巡检 → 停止再启动 → 已保存报告仍可读
```

## 怎样算完成

- [ ] 干净练习环境按说明能启动并完成业务闭环。
- [ ] 正常停止再启动保留数据；不能把健康依赖排序当作持续可用保证。
- [ ] 密钥未写入版本文件，关闭环境后端口释放；不使用清卷命令模拟普通重启。

## 本题常用写法（遇到再看）

【常见名字】service、network、volume、healthcheck。【易混】容器里的 127.0.0.1 指容器自身，不是宿主机上的另一个服务。
