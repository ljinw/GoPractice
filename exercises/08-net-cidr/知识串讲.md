## 标准库逐步读：地址、网段、包含关系和错误

本题继续做纯计算，不建立网络连接。先区分三个问题：IP文本能否解析；CIDR文本能否解析为范围；一个合法地址是否属于合法范围。第三个问题的false是正常结果，不是输入错误。

### ParseCIDR的三个返回值逐个看

~~~go
func ParseCIDR(s string) (IP, *IPNet, error)
func (n *IPNet) Contains(ip IP) bool
~~~

它们属于net。ParseCIDR接收CIDR字符串，返回原地址、掩码后的网络及错误。例如输入192.0.2.17/24，第一个地址是192.0.2.17，网段表示192.0.2.0/24。不要把原地址和网段当成两个同样的返回值。

IPNet包含IP和Mask字段。Mask表示前缀范围；Contains接收已解析IP，只返回bool，不返回第二个error。ParseCIDR失败时先处理err，不能直接调用可能为nil的network.Contains。

~~~go
_, network, err := net.ParseCIDR(cidrText)
~~~

_明确丢掉第一个地址。本题只需要范围，所以可以忽略；错误不应也用_丢掉。自己函数签名(bool, error)则是另一层业务合同，不是ParseCIDR原样返回。

### 完整小实验：观察主机位和包含结果

保存为本题warmup/cidr/main.go，运行go run ./warmup/cidr/main.go。

~~~go
package main

import (
    "fmt"
    "log"
    "net"
)

// main展示ParseCIDR的两个地址结果，并对比范围内外的输入。
func main() {
    host, network, err := net.ParseCIDR("192.0.2.17/24")
    if err != nil {
        log.Print(err)
        return
    }
    fmt.Printf("原地址=%s，网段=%s\n", host.String(), network.String())

    for _, text := range []string{"192.0.2.10", "198.51.100.10"} {
        ip := net.ParseIP(text)
        if ip == nil {
            log.Printf("地址无效：%q", text)
            continue
        }
        fmt.Printf("%s属于%s：%t\n", text, network.String(), network.Contains(ip))
    }
}
~~~

预期原地址.17、网段.0/24；第一个样本true，第二个false。将前缀只改为/32、/25、/33再分别预测；/33解析错误，不应该当成一个空网段来继续运算。

### 自己的(bool, error)怎样使用

调用InSubnet后，先看err。如果err != nil，输入/处理失败，暂时不解释bool；若err == nil，true与false都属于成功完成判断。

~~~text
非法IP或CIDR → false, error（错误带原因）
合法且属于   → true, nil
合法但不属于 → false, nil
~~~

IPv4业务限制要同时施加在地址输入与CIDR输入。先整理空白、拒绝本题不接受的IPv6文本形式，再检查库结果；不能因为某个To4可转换就放过所有含冒号输入。

/32只含一个IPv4地址；/0是整个IPv4范围。Contains是地址成员关系，不负责区分可用主机、网络地址和广播地址，也不决定该范围是否获准访问。这些业务约束需要另写明确规则。

## 与本题相连的原理和工程做法

### 错误、defer、context：程序要能收尾

`value, err := call()` 接住两个返回值。error 是接口，常规成功路径返回 nil，失败路径返回描述原因的错误。`if err != nil` 是常见判断；不要通过匹配错误字符串决定业务分支，优先使用稳定错误类型或 errors.Is/As。

defer 注册函数返回前执行的清理，例如关闭文件、释放锁。它不是“这一行马上执行清理”；普通调用的参数通常在注册 defer 时求值。循环里反复 defer 可能把资源保留到整个函数结束，长循环要缩短资源作用域。

context 传递取消、截止时间及少量请求范围信息。它不会强行杀死不配合的函数：下游调用要接受 ctx，循环要检查取消。不要把它当可随意塞业务字段的全局字典。

**重复学习：** 本题第一次跟写函数；HTTP 再看函数被谁调用；SQL 再接收 error；事务再用 defer；Worker 再练 context；Eino 再看接口和泛型。每次只补当前用途。


### 一次请求经过哪些边界

客户端先解析主机名，建立 TCP 连接；HTTPS 还要进行 TLS 握手和证书验证，之后发送 HTTP 请求。Nginx 可以终止 TLS，再与后端建立另一条连接。Go 服务按方法和路径选择处理器，读取请求、调用业务、写出状态码、响应头和正文。

因此“端口能连上”只说明连接层某一步成功，不说明 HTTP 路径存在、认证正确或 SQL 能执行。`connection refused`、连接超时、TLS 证书错误、HTTP 404、HTTP 500 是不同阶段的证据。排障时先把失败定位到阶段，再决定看哪一层。

TCP 提供字节流，没有“每次 Write 对应一次 Read”的消息边界。自定义协议要约定换行、长度前缀或其他 framing；读取需要限制最大长度，处理半包、粘包和对端关闭。网络课中的 echo 可以用换行分隔，再通过故意分两次写入一行来验证理解。
