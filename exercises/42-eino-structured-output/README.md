## 业务为什么需要它

看起来像答案的文字，可能包含不存在的事实。

## 这次做成什么

校验模型输出，再保存一条可查询的分析记录。

## 具体需求

POST /reports/{id}/analyses 只接受已完成报告；模型输出 summary、findings[{fact_ids,explanation}]、next_steps、unknowns。解析并校验必填字段及事实 ID，未知 fact_id 拒绝。成功 201 保存不可变 analysis_id、report_id、prompt_version、mode=fake/live；GET /analyses/{id} 按报告 owner 授权。异常输出不作为成功分析保存，也不修改报告结论。

## 输入与结果

```text
引用该报告 cpu 事实 → 接受；引用不存在的 cpu-999 → 分析失败
```

## 怎样算完成

- [ ] 合法输出可保存、重启后查询，关联正确报告。
- [ ] 坏 JSON、缺字段、伪造事实引用被拒绝。
- [ ] 无 CPU 数据时不能将缺失补成 0，也不能删除报告里的未知状态。

【常见词】schema、validation、grounding。【能力边界】结构与引用通过，不代表自然语言推理必然正确。
