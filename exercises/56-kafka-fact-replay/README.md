## 业务为什么需要它

统计程序升级后，希望从已有事实事件重新计算汇总，而不重新采集设备。

## 这次做成什么

用可回放事件重建一份非权威统计投影。

## 具体需求

合成事实事件含 event_id、tenant_id、device_id、schema_version；定义分区键与顺序范围。消费者以幂等规则更新统计，业务写入完成后管理 offset；新消费组回放得到相同统计。不改变原任务队列或报告事实权威来源，不把 Kafka 事务承诺扩大到外部数据库。

## 输入与结果

同一批事实，初次消费和新组回放都得到相同设备统计。

## 今天从这里动手

1. 先用纯函数确定固定事实集的预期汇总。
2. 记录 Topic、分区、消费组、保留与提交策略。
3. 在写统计后提交 offset 前中断，再用新组回放对照。

## 怎样算完成

- [ ] 相同事件重复或重投不重复计数。
- [ ] 新消费组能从保留范围内回放并重建一致结果。
- [ ] 消费者退出再启动能解释 offset、已提交结果与重放窗口。
