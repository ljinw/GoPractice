## 业务为什么需要它

用户需要统一地址访问 API 与 SSE，运维需要分清代理故障和应用故障。

## 这次做成什么

为原项目增加可验证的本机反向代理入口。

## 具体需求

教学 Nginx 转发 /api/ 到既有 API，明确路径重写、超时、请求编号与可信代理范围；SSE 使用适当缓冲和心跳策略。先用本机 HTTP 验证，TLS 以教学证书另行验证，不使用真实域名私钥。配置改动先校验再平滑重载。

## 输入与结果

经代理查询报告与分析进度；停止后端时入口呈现明确错误。

## 今天从这里动手

1. 先记录后端真实路径与端口，再套用讲义代理片段。
2. 检查上游收到的路径、头和 SSE 到达时间。
3. 制造端口错误与后端延迟，记录502/504相关证据而非只猜状态码。

## 怎样算完成

- [ ] 代理与直连返回同一业务结果，路径和身份没有被意外改写。
- [ ] SSE 能逐段到达，超时设置能解释，普通接口不被无限等待拖住。
- [ ] 错误上游端口可从日志定位，恢复配置后业务回归成功。
