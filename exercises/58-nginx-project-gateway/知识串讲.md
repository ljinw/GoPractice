## 带着项目问题读原理

### 为什么客户端不直接访问每个 Go 端口

Nginx 可以作为统一入口，管理域名、TLS、路由与反向代理。客户端连 Nginx，Nginx 再连后端，这两段都有自己的连接、超时与错误。负载均衡可以把请求分给多个实例，但会话、缓存和幂等不能依赖“下次一定还到同一进程”。

下面是配置片段，放在 nginx.conf 的 http 上下文内。它仅展示本机 HTTP 教学代理，不包含生产 TLS、日志、访问控制与完整主配置：

~~~nginx
upstream inspection_api {
    server 127.0.0.1:18080;
}

server {
    listen 127.0.0.1:18082;

    location /api/ {
        proxy_pass http://inspection_api/;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_connect_timeout 2s;
        proxy_read_timeout 15s;
    }
}
~~~

这里 /api/health 会被转到上游 /health，因为 proxy_pass 带 URI 尾部 /；去掉这部分后路径处理会不同。不要只“看着差不多”，要用上游访问日志验证收到的真实路径。[Nginx proxy 模块](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)。

上面假定 Nginx 与 Go 在同一主机网络空间。若 Nginx 在容器里，127.0.0.1 指向 Nginx 自己，不能据此访问另一个容器。需改用所在网络的服务名和容器内端口。

### 502、504、TLS 错误怎样区分

502 常涉及上游连接或响应异常；504 常涉及等待上游超时。具体原因仍看 error log、upstream 地址和时间，而不是只按状态码猜。后端可能仍在执行已经被代理判超时的操作，所以客户端重试需要幂等。

TLS 排障看证书有效期、域名匹配、证书链、时间与握手协议。证书续期后还要确认入口实际加载新证书。内部 HTTP/HTTPS 转发策略取决于信任边界，不因“在内网”就自动可信。

X-Forwarded-For 可能包含客户端伪造值。应用只应信任明确配置的代理链并采用正确解析策略；不能直接把最左端字符串作为可信源 IP。X-Request-ID 也要有统一生成与校验策略，避免每层随意覆盖丢失关联。

### SSE、请求体与配置更新

流式接口可能需要关闭对应 location 的响应缓冲，并设置与心跳间隔匹配的读超时。proxy_read_timeout 是两次读取之间的间隔约束，不是简单的整个响应总时长。普通接口与 SSE 分开设置，不全局拉长所有超时。

上传大小、请求头大小、客户端慢发送同样需要限制。Nginx 限流与应用限流各有位置，最终仍要保护数据库和模型等共享资源。

更新配置先做语法校验，再 reload，再检查入口请求、错误日志和新 worker 状态。reload 支持平滑替换进程，但配置正确不等于业务路由正确。[Nginx 入门与配置重载](https://nginx.org/en/docs/beginners_guide.html)。


## 把例子接回现有项目

教学 Nginx 转发 /api/ 到既有 API，明确路径重写、超时、请求编号与可信代理范围；SSE 使用适当缓冲和心跳策略。先用本机 HTTP 验证，TLS 以教学证书另行验证，不使用真实域名私钥。配置改动先校验再平滑重载。

### 输入如何走到结果

经代理查询报告与分析进度；停止后端时入口呈现明确错误。

### 分步动手

1. 先记录后端真实路径与端口，再套用讲义代理片段。
2. 检查上游收到的路径、头和 SSE 到达时间。
3. 制造端口错误与后端延迟，记录502/504相关证据而非只猜状态码。

### 读完后检验是否理解

先口述本题输入、需要改变的模块、权威数据在哪里、失败怎样被发现，再去 [需求与验收](README.md) 实现。讲义配置和表名是示意，先核对已有项目再使用；一处知识卡住可以单独练小片段，业务验收仍以实际运行证据为准。
