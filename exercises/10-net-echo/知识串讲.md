## 标准库逐步读：监听器、连接、字节流与行协议

net/http已经帮你解析了HTTP。用net直接做TCP时，只得到字节流，需要自己约定一条消息何时结束、怎样回复、谁关闭、等多久。本题约定一行以\n结尾，每个连接只处理一行。

### 从Listen到Accept：两种不同对象

~~~go
func Listen(network, address string) (Listener, error)
type Listener interface {
    Accept() (Conn, error)
    Close() error
    Addr() Addr
}
~~~

net.Listen("tcp", "127.0.0.1:19090")申请监听入口，可能因地址/端口占用等失败；成功返回Listener。它不是客户端的连接。

ln.Accept()等待一个客户端连接，成功返回Conn。ln关闭会使等待的Accept结束并报错。一个客户端conn.Close()通常只结束这一条连接，不等于ln.Close()关闭服务入口。服务要连续处理多个客户端，需要外层Accept循环；初次先串行，之后再学并发。

端口0用于Listen时表示让系统分配端口，测试可用；09题对远端端口0的拒绝是自己的探测业务规则，两者不冲突。正式本题监听端口仍按README固定19090。

### Read、Write和Deadline签名

~~~go
Read(b []byte) (n int, err error)
Write(b []byte) (n int, err error)
Close() error
SetDeadline(t time.Time) error
SetReadDeadline(t time.Time) error
SetWriteDeadline(t time.Time) error
~~~

这是Conn的部分方法。Read把字节写入你提供的缓冲区；返回n说明这次拿到了多少字节，可能比缓冲区小，也可能与消息边界完全无关。n>0与err非nil可以同时出现，处理时不能不看n就丢掉已经读到的数据；具体协议决定这些数据是否足够形成完整消息。

Write写出的n也不是HTTP状态；发生错误时要按合同处理。fmt.Fprintln(conn, "ping")会格式化并写入连接，追加换行，返回字节数和error。

Deadline接收绝对时间点，例如time.Now().Add(2 * time.Second)，不是传入2 * time.Second本身。到期影响后续及挂起的I/O，直到重新设置；不会因为每次读到一个字节自动续期。零时间点可清除期限；读写也可分开设。

### 为什么需要bufio.Reader.ReadString

~~~go
func NewReader(rd io.Reader) *Reader
func (b *Reader) ReadString(delim byte) (string, error)
~~~

属于bufio。NewReader(conn)在连接之上做缓冲读取；ReadString('\n')读到换行，结果包含该换行。'\n'是字符字面量，适合作为单字节分隔符；"\n"是字符串，不是同一种参数类型。

未找到换行就遇到EOF/超时，ReadString会同时返回已经读到的部分文字与error。本题要求完整行，所以部分文字不能当成有效ping直接成功；可以记录诊断后结束这一条连接。多条消息在一次底层Read里到达也不稀奇，按分隔规则解码，不按Read调用次数认消息。

### 完整小实验：只收一条连接，回显一行

保存为本题warmup/line/main.go。这个演示使用19091，与正式题的19090分开；只处理一个客户端后退出，用来观察对象与生命周期。回显协议不是正式ping/pong合同。

~~~go
package main

import (
    "bufio"
    "fmt"
    "log"
    "net"
    "time"
)

// handleLine拥有本条连接；要求完整LF行，失败返回原因并清理连接。
func handleLine(conn net.Conn, timeout time.Duration) error {
    defer func() {
        if err := conn.Close(); err != nil {
            log.Printf("关闭连接失败: %v", err)
        }
    }()

    if err := conn.SetDeadline(time.Now().Add(timeout)); err != nil {
        return fmt.Errorf("设置读写期限失败: %w", err)
    }

    line, err := bufio.NewReader(conn).ReadString('\n')
    if err != nil {
        return fmt.Errorf("读取完整行失败，已读内容=%q: %w", line, err)
    }
    if _, err := fmt.Fprintf(conn, "echo:%s", line); err != nil {
        return fmt.Errorf("写回复失败: %w", err)
    }
    return nil
}

// main负责监听与接入；单条连接处理细节交给handleLine。
func main() {
    listener, err := net.Listen("tcp", "127.0.0.1:19091")
    if err != nil {
        log.Print(err)
        return
    }
    defer func() {
        if err := listener.Close(); err != nil {
            log.Printf("关闭监听器失败: %v", err)
        }
    }()

    log.Printf("准备接收一条连接：%s", listener.Addr().String())
    conn, err := listener.Accept()
    if err != nil {
        log.Print(err)
        return
    }
    if err := handleLine(conn, 2*time.Second); err != nil {
        log.Print(err)
    }
}
~~~

客户端可复用09题的Dial写法连接19091，再检查SetDeadline返回值，fmt.Fprintln(conn, "ping")发送，bufio.NewReader(conn).ReadString('\n')收回复；每个调用仍检查error并关闭连接。这里只缺你的客户端组合练习，不用HTTP的状态码解释这份TCP回显协议。

### 变式、边界和正式题如何迁移

先完整发送ping\n；再分两次发送"pi"与"ng\n"；再一次发送"ping\nhello\n"，观察本例只处理第一行后关闭。最后只发ping不加换行，期限到后该连接应结束。

演示的ReadString没有设置最大行长度，适合当前明确的本机小消息实验；后续扩展应增加总字节限制，不能把读写期限等同于内存大小限制。协议当前只约定LF，CRLF怎样处理应另写清，不能无限TrimSpace误删有意义内容。

把示例迁回正式题时，先根据完整行判断ping/其他输入，再实现外层串行Accept循环。单条连接错误交给该连接处理，不因为一个断开的客户端就Fatal退出整个服务；监听器关闭与持续接入错误的处理则是服务级问题。不要在永不结束的Accept外层循环里不断积压defer conn.Close()，把每条连接的清理放到它自己的处理函数。

源码先看Listener.Accept合同、Conn的Read/Write与期限合同、ReadString的返回内容和EOF行为。C#的NetworkStream同样是流，Read一次不自动等于一条消息；对照StreamReader时也要核对换行与EOF规则。

## 与本题相连的原理和工程做法

### 一次请求经过哪些边界

客户端先解析主机名，建立 TCP 连接；HTTPS 还要进行 TLS 握手和证书验证，之后发送 HTTP 请求。Nginx 可以终止 TLS，再与后端建立另一条连接。Go 服务按方法和路径选择处理器，读取请求、调用业务、写出状态码、响应头和正文。

因此“端口能连上”只说明连接层某一步成功，不说明 HTTP 路径存在、认证正确或 SQL 能执行。`connection refused`、连接超时、TLS 证书错误、HTTP 404、HTTP 500 是不同阶段的证据。排障时先把失败定位到阶段，再决定看哪一层。

TCP 提供字节流，没有“每次 Write 对应一次 Read”的消息边界。自定义协议要约定换行、长度前缀或其他 framing；读取需要限制最大长度，处理半包、粘包和对端关闭。网络课中的 echo 可以用换行分隔，再通过故意分两次写入一行来验证理解。

### 错误、defer、context：程序要能收尾

`value, err := call()` 接住两个返回值。error 是接口，常规成功路径返回 nil，失败路径返回描述原因的错误。`if err != nil` 是常见判断；不要通过匹配错误字符串决定业务分支，优先使用稳定错误类型或 errors.Is/As。

defer 注册函数返回前执行的清理，例如关闭文件、释放锁。它不是“这一行马上执行清理”；普通调用的参数通常在注册 defer 时求值。循环里反复 defer 可能把资源保留到整个函数结束，长循环要缩短资源作用域。

context 传递取消、截止时间及少量请求范围信息。它不会强行杀死不配合的函数：下游调用要接受 ctx，循环要检查取消。不要把它当可随意塞业务字段的全局字典。

**重复学习：** 本题第一次跟写函数；HTTP 再看函数被谁调用；SQL 再接收 error；事务再用 defer；Worker 再练 context；Eino 再看接口和泛型。每次只补当前用途。


### 三个问题分别处理

Go map 被并发读写是进程内共享内存问题，可用 Mutex 等同步。两次 HTTP 请求创建同一个任务，是业务幂等问题，要靠稳定业务键、唯一约束和结果复用。多个实例争抢一份执行权，是分布式协调问题，可能涉及租约、条件更新或分布式锁。

goroutine 让函数并发运行，channel 在 goroutine 之间通信。channel 不是持久队列，进程退出后内容不保证保留。无限启动 goroutine 会把压力转移到数据库和网络；Worker 池、队列容量及背压共同限制并发。
