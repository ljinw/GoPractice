## 业务为什么需要它

任务慢可能发生在排队、查询、模型或结果保存，需要跨进程证据。

## 这次做成什么

将原同步追踪延伸到异步任务的因果关系。

## 具体需求

发布事件携带允许的追踪上下文，消费端按选定语义继续或链接 Span；模型和存储步骤分别计时，job_id 关联独立请求。配置本机 Collector 与一个后端，不把敏感正文塞入属性；采样范围写清。

## 输入与结果

同一 job_id → API接收 Trace、消息交付关系、Worker与模型步骤。

## 怎样算完成

- [ ] 人工增加的某一步延迟在追踪与实际耗时上相符。
- [ ] 异步操作与原任务可关联，新的查询请求不复用旧请求身份。
- [ ] 故意移除上下文能观察断链，修复后恢复；未采样边界如实记录。
