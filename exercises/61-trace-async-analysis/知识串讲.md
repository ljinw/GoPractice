## 带着项目问题读原理

### Trace 与 Span 怎样关联

Trace 表示一次相关操作的整体路径；Span 表示其中一个有起止时间的步骤，例如 HTTP、SQL、RPC。父子关系与上下文传播把它们连起来；异步任务也可以通过链接表达因果关系。

OpenTelemetry 提供采集和传播等规范与组件，Collector 接收、处理和导出遥测；Jaeger、Tempo 等可作为追踪后端。装了 SDK 不等于已经有可查询的追踪存储。[OpenTelemetry Traces](https://opentelemetry.io/docs/concepts/signals/traces/)。

HTTP/RPC 边界要提取与注入上下文；数据库或客户端操作创建相应 Span；消息发布时携带允许的追踪信息，消费时继续或链接。Baggage 会传播数据，不能随意放密码或完整用户资料。

### Request ID、Trace ID、Job ID 为什么都要留

Request ID 对应一次入口交互；Trace ID 用于跨步骤追踪；Job ID 对应持久化业务任务，可能横跨多次请求、重试和追踪。用户第二天查询任务时，新的 Request ID 不该改变任务身份。

假设接口总耗时 2 秒，SQL Span 只有 20 毫秒，RPC 却 1.8 秒，就先看 RPC；若请求等待连接池的时间没有被记录，图上可能仍缺失一段。追踪能帮助定位，但仪表覆盖范围和采样会影响可见性。

错误状态、超时和重试要能在 Span 属性或事件中看出；避免写完整 SQL 参数、token 或报告正文。采样会漏掉部分请求，需要与日志、指标结合，不能因查询不到 Trace 就断言请求没有发生。


### Agent 工具、流式输出与成本

Tool 是可以被调用的能力，应有输入校验、最小权限、超时、调用次数与审计。读到的文档或设备输出可能包含诱导性文字，它们属于数据，不能提升为操作授权。初始工具只做获准范围内的只读查询。

SSE 持续输出进度或文本，但任务结果仍应持久化。浏览器断线后能按 job_id 查询状态；不能只在内存流里保存唯一结果。Nginx 缓冲、代理读超时、客户端取消都可能影响体验，[第 58 题讲义](../58-nginx-project-gateway/知识串讲.md)。

模型慢或限额不足时要排队/降级，控制总 token、并发、最大步骤数和成本。日志记录供应商、模型配置版本、耗时、用量与错误分类，避免原样收集敏感提示词。质量评估使用固定事实集：是否引用正确、是否承认缺失、是否越权、是否杜撰。
