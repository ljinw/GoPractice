## 业务为什么需要它

用户需要知道请求是否被接收，以及稍后到哪里查结果。

## 这次做成什么

创建一个持久化任务，并能查到它的状态。

## 具体需求

POST /inspection-jobs，正文 {"device_id":1}；成功 202 返回 job_id、status=queued 和查询地址。GET /inspection-jobs/{id} 返回该任务。创建时检查设备存在且启用，冻结设备名/IP/样例标识，记录 owner_id、created_at；停用返回 409，不存在返回 404。owner 由服务端当前用户提供，教学阶段使用可注入 demo 用户，第 29 题接认证。

## 输入与结果

```text
提交 sw-core → 202 + job_id；重启后查询仍为 queued
```

## 怎样算完成

- [ ] 任务有唯一编号，重启后可查。
- [ ] 停用、缺失设备不会新增任务；客户端不能指定 owner_id。
- [ ] 修改设备名称后，已有任务的设备快照不变。

## 本题常用写法（遇到再看）

【业务约定】202 是已受理，不代表巡检通过。【常用写法】Job、jobID、GetJob；业务编号由服务器生成。
