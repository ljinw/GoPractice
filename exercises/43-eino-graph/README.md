# 43 · 把分析过程拆成可检查的步骤

阶段：Eino Graph。前置：第 42 题。

## 先学再练：本题串讲

打开本目录的 [知识串讲](知识串讲.md)，先学这题需要的语法、原理和常用写法，再回来实现下面的业务需求。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

知道模型出错还不够，要知道是取事实、组织提示还是输出校验失败。

## 这次做成什么

用 Graph 编排已有分析步骤，保留统一入口。

## 具体需求

把已实现的授权后取报告、准备输入、调用模型、校验、保存连接成有类型边界的节点。任一步失败停止后续保存；添加节点名、耗时与错误回调。重用 41、42 的同一套规则，不保留另一条绕开校验的直连模型路径。

## 输入与结果

```text
模型节点返回坏 JSON → 校验节点失败 → 保存节点没有执行
```

## 怎样算完成

- [ ] 正常路径得到与原来相同的合法分析。
- [ ] 对每个节点注入错误，定位正确且不产生成功记录。
- [ ] 一次分析请求只调用一次模型；节点重复回调不会造成重复落库。

## 本题常用写法（遇到再看）

【Eino 名字】Node、Edge、Compile、Invoke、Callback。【阅读方式】先画清输入输出，再查当前锁定版本的具体方法签名。
