## 带着项目问题读原理

### 一次运行依赖哪些东西

可执行文件要匹配操作系统与 CPU 架构；动态链接或 CGO 可能还需要系统库。进程有运行用户、工作目录、环境变量、文件权限、监听地址、打开文件与信号处理。Windows 上能运行的二进制不能直接当 Linux 服务启动。

配置分为默认值、环境专属值和密钥。启动时检查必需配置，日志显示版本和非敏感配置摘要。配置文件使用绝对路径或明确工作目录；“在我的终端能启动，服务管理器里失败”常常与目录、权限、环境不同有关。

学习服务器阶段可以用 Linux 虚拟机或 WSL2 中的隔离环境。systemd 可用性要检查环境设置，不假设每个 WSL 环境都相同。先明确目录和端口，再运行服务，不连接真实设备。

### 常用检查命令分别回答什么

以下是 Linux 只读诊断命令；服务名 inspection-api 为示意，需要存在相应 unit：

~~~bash
systemctl status inspection-api
journalctl -u inspection-api --since "10 minutes ago"
ss -lntp
ps -ef
free -h
df -h
df -i
~~~

status 看管理器状态，journalctl 看进程日志，ss 看监听，ps 看进程，free 看内存，df -h 看磁盘空间，df -i 看 inode。磁盘还有容量但 inode 用完，也可能无法创建日志文件。执行权限、目录权限、只读文件系统是另外的失败原因。

CPU 高先找忙的进程/线程与请求类型；内存增长要区分缓存、堆、连接和 goroutine 泄漏；负载高不一定全是 CPU 忙，也可能有 I/O 等待。Go 的 pprof 能帮助定位，但诊断接口应受保护，不能直接暴露公网。

### 优雅停止是业务功能

收到 SIGTERM 后，先停止接收新工作，再给正在处理的请求与任务有限时间收尾，关闭监听与连接。HTTP Server.Shutdown 和应用 Worker 停止是不同部分；关闭 HTTP 不会自动安全停掉所有 goroutine。

Worker 应明确是否继续当前任务、多久后放弃、怎么让其他 Worker 接管。已经提交结果但尚未确认消息的窗口，依靠幂等处理。运行管理器、容器与 Kubernetes 的终止宽限时间必须容纳应用的收尾预算。


## 把例子接回现有项目

在隔离 Linux 环境管理 API 与 Worker，明确运行用户、目录、配置与日志；使用可用的服务管理器，缺失必需配置时启动失败。停止时拒绝新任务并按有限预算收尾，未完成任务沿原恢复协议接管，不丢弃为无记录 goroutine。

### 输入如何走到结果

启动→提交延迟任务→正常停止→重新启动，任务最终完成或进入明确可恢复状态。

### 分步动手

1. 先核对 Linux 架构、二进制、用户和目录权限。
2. 配置服务管理并用只读命令确认实际启动信息。
3. 在任务执行中发送正常停止信号，测量收尾和恢复。
