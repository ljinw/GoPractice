# 31 · 缓存已完成报告并保留权限检查

阶段：Redis。前置：第 30 题。

## 业务为什么需要它

同一份报告会被多次刷新，内容又不会变化。

## 这次做成什么

让报告重复查询优先命中 Redis，缓存故障可退回数据库。

## 具体需求

只缓存不可变报告，TTL 60 秒。先查权限，再按 report:v1:{owner}:{reportID} 读缓存；未命中查库并回填。Redis 断开或内容损坏时回源并记录故障。任务状态和尚未完成的 AI 分析不放入这个不可变缓存。

## 输入与结果

```text
首次查报告 → 数据库；第二次 → 缓存；Redis 停止 → 仍能从数据库查询
```

## 怎样算完成

- [ ] 用仓储调用次数证明第二次命中缓存。
- [ ] Redis 停止、过期或缓存损坏时仍返回正确报告。
- [ ] bob 即使猜中缓存 key，也不能读到 alice 的报告。

## 本题常用写法（遇到再看）

【常用写法】rdb 区别于 SQL 的 db，Key 加版本和业务前缀。【概念】cache-aside：业务决定读缓存、回源和回填。
