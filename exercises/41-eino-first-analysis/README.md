# 41 · 让 Eino 接住一份巡检报告

阶段：Eino ChatModel。前置：第 40 题。

## 先学再练：本题串讲

打开本目录的 [知识串讲](知识串讲.md)，先学这题需要的语法、原理和常用写法，再回来实现下面的业务需求。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

AI 需要读到实际事实，才能解释这次异常。

## 这次做成什么

建立唯一分析入口，用 Eino 模型组件处理报告事实。

## 具体需求

在 inspection 服务内增加 AnalysisService.AnalyzeReport；统一从该入口经过授权、事实读取、ChatTemplate/Message 与 ChatModel 调用。默认注入假 ChatModel，返回固定可观察内容。输入含 report_id、fact_id、值与规则；缺事实必须说明未知。模型凭据、原始配置不进入提示词。

## 输入与结果

```text
CPU=92、规则>=80 → 假模型返回教学解释；报告本身保持不变
```

## 怎样算完成

- [ ] 假模型确实收到该报告事实和编号，而非空泛提问。
- [ ] 未授权用户被拒绝，模型调用次数为 0。
- [ ] 假模型超时或报错会显式失败，不写“分析成功”。

## 本题常用写法（遇到再看）

【Eino 名字】ChatModel 是模型调用能力，Message 是输入输出消息，ChatTemplate 组织内容；它们不是模型权重。【约定】所有模型调用都走一个分析入口。
