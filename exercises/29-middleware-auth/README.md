# 29 · 只允许用户查看自己的任务

阶段：HTTP 中间件。前置：第 28 题。

## 先学再练：本题串讲

打开本目录的 [知识串讲](知识串讲.md)，先学这题需要的语法、原理和常用写法，再回来实现下面的业务需求。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

知道一个任务编号，不应等于有权读报告。

## 这次做成什么

用认证中间件和业务授权保护任务与报告。

## 具体需求

使用环境配置的两组本地练习 Token 映射 alice、bob，Authorization: Bearer 携带。缺失或错误凭据 401；登录后按 owner_id 查询，其他人的任务统一 404。owner 不取自请求正文。认证身份放请求上下文；所有任务、报告及后续缓存/分析入口复用授权检查。设备目录暂为共享练习资源。

## 输入与结果

```text
alice 创建任务 → alice 可查询；bob 用同 ID 查询 → 404
```

## 怎样算完成

- [ ] 无凭据、坏凭据、有效凭据分别拒绝/拒绝/通过。
- [ ] bob 不能读取 alice 的状态或报告，也不能伪造 owner_id。
- [ ] 错误日志和响应不包含完整 Token；失效配置启动时报错。

## 本题常用写法（遇到再看）

【概念】认证说明是谁，授权说明能做什么。【惯例】HTTP middleware 在业务处理器前检查；上下文键用自定义类型。
