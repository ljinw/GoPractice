# 39 · 沿一次请求找到慢在哪里

阶段：日志与 OpenTelemetry。前置：第 38 题。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

拆成服务和队列后，只看一行错误很难定位。

## 这次做成什么

把提交、RPC 和后台执行关联起来。

## 具体需求

记录 request_id、job_id、trace_id 与阶段耗时；HTTP/gRPC 传播上下文，outbox/Stream 保存可传播的 trace 信息，worker 建立关联 span。记录成功/失败和依赖耗时。先用本地导出或测试导出器检查，再接本地查看器。日志不记录 Token、模型密钥或整份敏感输入。

## 输入与结果

```text
任务慢 → 查到 inventory 20ms、排队 300ms、执行 2s
```

## 怎样算完成

- [ ] 能从 job_id 找到入口、RPC、worker 三段证据。
- [ ] RPC 超时能定位到对应 span，而不是所有阶段都标成功。
- [ ] 敏感值不在日志/trace 中，排队阶段上下文不会凭空丢失。

## 本题常用写法（遇到再看）

【概念】log 是事件记录，trace 是跨步骤关联，metric 是聚合计数；本题先做前两项。
