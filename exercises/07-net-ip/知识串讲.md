## 标准库逐步读：IP文本、IP值与业务允许范围

net包不等于“所有网络相关内容”。ParseIP/ParseCIDR做解析与地址运算，不产生设备连接；Dial/Listen才涉及连接和监听。先掌握对象及返回值，再判断代码有没有实际网络副作用。

### ParseIP为什么没有error返回值

~~~go
func ParseIP(s string) IP
func (ip IP) To4() IP
func (ip IP) String() string
~~~

这几项属于net。IP是一种可保存地址字节的类型；ParseIP接受字符串，返回IP，解析失败用nil表达。不能写ip, err := net.ParseIP(...)，因为它只有一个返回值。

To4是IP值的方法，尝试取得IPv4形式，不能转成IPv4时返回nil。它不发送探测包，不判断路由是否可达。String把IP格式化为文本，不是对端设备回传的内容。

空白整理来自strings.TrimSpace，net.ParseIP本身不替本题保证全部输入整理。Hostname不是IP文本，ParseIP("sw-core")返回nil；需要名称解析是另一个API与可能的网络动作。

### 库支持范围与本题限制分别写清

ParseIP支持IPv4和IPv6。某些IPv4映射IPv6文本也能得到非nil To4，所以“只检查To4”不能保证原输入是本题要求的不带冒号IPv4文本。

本题业务合同：整理后，文本中含冒号的IPv6形式明确拒绝；然后用ParseIP与To4确认格式。冒号判断是本题规则，不是标准库只支持IPv4。不要把nil、false和HTTP400当成同一种层次：nil是库结果，false可能是你的校验结果，400由HTTP层选择。

### 完整小实验：只解析，不连接

保存为本题warmup/ip/main.go，运行go run ./warmup/ip/main.go。

~~~go
package main

import (
    "fmt"
    "net"
    "strings"
)

// main并列观察库的解析能力与本题的IPv4文本限制。
func main() {
    inputs := []string{
        " 192.0.2.10 ",
        "999.1.1.1",
        "sw-core",
        "2001:db8::1",
        "::ffff:192.0.2.10",
        "",
    }

    for _, raw := range inputs {
        text := strings.TrimSpace(raw)
        ip := net.ParseIP(text)
        if ip == nil {
            fmt.Printf("输入=%q，无法解析\n", raw)
            continue
        }

        allowed := !strings.Contains(text, ":") && ip.To4() != nil
        fmt.Printf("输入=%q，库格式化=%s，本题允许=%t\n",
            raw, ip.String(), allowed)
    }
}
~~~

!取布尔反值；&&表示两个条件都成立才通过。只改变映射IPv6那一项，分别只看To4和保留原文本限制，比较结果。不要为了通过样例把判断写成固定字符串列表。

### 接回HTTP与源码问题

先把校验写成可单独调用的纯函数，再由/device-preview读取字符串并使用它。库的解析不依赖HTTP，可以复用到命令行与测试；HTTP层才负责选择400及JSON错误正文。

输入合法只证明地址格式，不证明属于获准资产、在线、有端口、能认证或能完成业务。后续08做范围，09做连接，10做自定义消息，分别获取不同证据。

源码看ParseIP解析失败的出口、To4识别的表示范围；不必一开始追完整地址解析器。C#的IPAddress.TryParse还需核对它接受的文本形式，不能把两种解析器的所有边界假定一样。

## 与本题相连的原理和工程做法

### 变量、零值、判断：别只认符号

`x := 1` 用于函数体内的短变量声明；`x = 2` 给已有变量赋值。`var count int` 创建整数变量并使用零值 0。`var enabled bool` 的零值是 false；string 的零值是空字符串。零值是语言提供的初始值，不一定等于业务上的“合法默认值”。

`if enabled { ... }` 要求条件是布尔值。`==` 比较，`=` 赋值，`!=` 表示不等。Go 不会把非零整数自动当成 true。尽早返回错误能减少嵌套：先拒绝非法输入，剩下代码处理正常情况。

对设备 CPU 数据来说，0 表示一次有效的 0% 采样；缺失则应使用额外状态或可空字段。直接把缺失解析成 0，会把“没采到”误报为“正常”。

### 一次请求经过哪些边界

客户端先解析主机名，建立 TCP 连接；HTTPS 还要进行 TLS 握手和证书验证，之后发送 HTTP 请求。Nginx 可以终止 TLS，再与后端建立另一条连接。Go 服务按方法和路径选择处理器，读取请求、调用业务、写出状态码、响应头和正文。

因此“端口能连上”只说明连接层某一步成功，不说明 HTTP 路径存在、认证正确或 SQL 能执行。`connection refused`、连接超时、TLS 证书错误、HTTP 404、HTTP 500 是不同阶段的证据。排障时先把失败定位到阶段，再决定看哪一层。

TCP 提供字节流，没有“每次 Write 对应一次 Read”的消息边界。自定义协议要约定换行、长度前缀或其他 framing；读取需要限制最大长度，处理半包、粘包和对端关闭。网络课中的 echo 可以用换行分隔，再通过故意分两次写入一行来验证理解。
