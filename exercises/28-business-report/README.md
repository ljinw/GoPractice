# 28 · 给用户一份不会随数据变化的报告

阶段：业务闭环。前置：第 27 题。

## 先学再练：本题串讲

打开本目录的 [知识串讲](知识串讲.md)，先学这题需要的语法、原理和常用写法，再回来实现下面的业务需求。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

用户回看昨天的结论时，需要看到当时的证据。

## 这次做成什么

生成并查询一份不可变巡检报告。

## 具体需求

GET /inspection-jobs/{id}/report：未完成返回 409，成功返回报告，未知任务 404。报告保存 report_id、设备快照、事实、规则版本、正常/异常/未知与原因。用唯一 job_id 防重复；本题将任务成功、事实和报告的完成提交收敛到同一事务。报告生成后不因设备编辑或规则修改而重算。

## 输入与结果

```text
CPU 92，教学阈值 80 → 异常；报告列出对应 fact_id 和比较过程
```

## 怎样算完成

- [ ] 报告能回答：哪台设备、测到什么、为什么这样判。
- [ ] 改设备名称或把当前阈值改成 95，旧报告内容不变。
- [ ] 报告写入故障时不能留下 succeeded 却查不到报告的任务。

## 本题常用写法（遇到再看）

【常用写法】ReportSnapshot、ruleVersion、evidence。【业务约定】后续 AI 分析作为关联记录保存，不覆盖事实报告。
