## 与本题相连的原理和工程做法

### 一组数据：结构体、切片、map

~~~go
// 示意：这些类型定义放在函数外。
type Device struct {
    ID      int64  `json:"id"`
    Name    string `json:"name"`
    Enabled bool   `json:"enabled"`
}
~~~

结构体把相关字段放在一起；JSON 标签告诉编码器外部字段叫什么，它不是变量声明。`[]Device` 是设备切片；`map[string]Device` 用字符串找设备。`for _, device := range devices` 遍历切片；下划线表示忽略这次不需要的下标。

读取 map 时常用 `device, ok := byName[name]`。ok 用来区分“没有这个键”和“这个键对应一个零值”。nil map 可以读，但不能直接写入；需要先 make 或使用字面量创建。普通 map 的并发读写必须有同步措施。

切片由底层数组及描述信息支持。复制切片变量不等于复制所有元素；多个切片可能共享数据。保存历史报告时若还引用同一份可变数据，后来修改设备可能影响“历史”。业务上需要复制必要字段或序列化为独立快照。

### 表不是装 JSON 的抽屉

设备表保存设备当前资料；任务表保存一次执行请求；报告表保存结果快照。它们的生命周期不同。报告不能查询时再临时拼接最新设备名，否则设备改名会改写历史解释。

主键给每行稳定标识；唯一约束防止重复业务键；外键维护关联；NOT NULL 和 CHECK 表达允许的数据范围。应用校验负责给友好提示，数据库约束负责在并发下守住底线。两者同时存在有意义。

以下为 MySQL 8.4/InnoDB 教学表，明确用于隔离数据库，时间统一写入 UTC：

~~~sql
CREATE TABLE reports (
    id BIGINT PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    job_id BIGINT NOT NULL,
    status VARCHAR(20) NOT NULL,
    created_at DATETIME(6) NOT NULL,
    UNIQUE KEY uq_report_job (tenant_id, job_id)
) ENGINE=InnoDB;
~~~

这里的联合唯一约束允许不同租户各自使用相同 job_id，但同一租户不能重复产生同一任务报告。若你的 job_id 已全局唯一，也可以选择相应全局约束；必须与业务 ID 策略一致。
