# 30 · 重复点击也只创建一个任务

## 业务为什么需要它

浏览器重试或网络超时后重发，不应产生重复巡检。

## 这次做成什么

相同创建意图只能落下一条任务。

## 具体需求

POST /inspection-jobs 增加 Idempotency-Key；按 owner_id + key 建唯一约束，并保存规范化输入摘要及首次响应。相同 key 和参数返回原 job_id；同 key 不同参数 409。任务创建和幂等记录同一事务。空 key 为 400；校验失败不占 key；先认证再处理 key。

## 输入与结果

```text
同用户连点两次、同 key 同设备 → 同一 job_id；换设备但不换 key → 409
```

## 怎样算完成

- [ ] 串行重试返回同一编号，总任务数只增 1。
- [ ] 两个并发请求同 key，结果指向同一任务。
- [ ] 不同用户的 key 不串用；事务失败后可重试，不留永久半成品。

## 本题常用写法（遇到再看）

【业务约定】请求编号用于排查，幂等键用于识别一次操作，二者用途不同。【常用做法】数据库唯一约束兜底并发。
