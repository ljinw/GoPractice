## 标准库逐步读：怎样在不开固定端口时观察响应

本题不是先学习测试框架花样，而是学会用标准库拿到可核对的HTTP结果。先理解一次“准备输入→调用处理器→检查输出”，再把多种输入放进表格。

### 三个常用构造函数不是同一个用途

~~~go
func NewRequest(method, target string, body io.Reader) *http.Request
func NewRecorder() *ResponseRecorder
func NewServer(handler http.Handler) *Server
~~~

都属于net/http/httptest包。NewRequest创建服务端测试请求，给处理器使用，不发送网络。NewRecorder创建内存里的响应记录器，实现ResponseWriter；因此可以作为w传入。NewServer才会启动本机临时端口服务器，适合让Client真正发请求；完成后必须Close。

NewRequest采用便于测试的接口，错误输入可能panic；若测试构造失败本身是目标，要选择相应有error返回的构造API，不从这个返回值数量推断所有NewRequest都一样。

### Recorder为什么有Code，而普通w没有

ResponseRecorder是具体测试结构体，有Code、Body等字段；ResponseWriter是接口，只约定Header、WriteHeader、Write等能力。把Recorder交给处理函数不改变这份接口合同；你在测试代码里保留具体Recorder变量，才有额外字段可读。

~~~go
func (rw *ResponseRecorder) Result() *http.Response
~~~

Result得到模拟客户端收到的响应对象。用resp.StatusCode和resp.Header检查更接近对外结果；Result可表达隐式200。不要在处理完后继续修改响应再假定Result里所有快照自动跟着变；按完整处理结束后的结果检查。

### 一份可独立运行的小测试

保存为本题warmup/recorder/reply_test.go，运行go test -v ./warmup/recorder/reply_test.go。这是独立测试文件，不需要业务main函数，也不依赖现有固定端口。

~~~go
package main

import (
    "fmt"
    "log"
    "net/http"
    "net/http/httptest"
    "testing"
)

// reply是独立教学处理器；写入失败单独报告，不改变已写出的状态。
func reply(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "text/plain; charset=utf-8")
    w.WriteHeader(http.StatusCreated)
    if _, err := fmt.Fprintln(w, "created"); err != nil {
        log.Print(err)
    }
}

// TestReply用内存请求/记录器检查状态、头和正文。
func TestReply(t *testing.T) {
    request := httptest.NewRequest("GET", "/example", nil)
    recorder := httptest.NewRecorder()

    reply(recorder, request)

    response := recorder.Result()
    defer func() {
        if err := response.Body.Close(); err != nil {
            t.Errorf("关闭测试响应失败: %v", err)
        }
    }()

    if response.StatusCode != http.StatusCreated {
        t.Errorf("状态码=%d，期望201", response.StatusCode)
    }
    if got := response.Header.Get("Content-Type"); got != "text/plain; charset=utf-8" {
        t.Errorf("Content-Type=%q", got)
    }
    if got := recorder.Body.String(); got != "created\n" {
        t.Errorf("正文=%q", got)
    }
}
~~~

这个教学reply沿用01题记录写入错误的策略。测试的错误用t.Error/Fatal报告，不使用log.Fatal终止整个测试进程。

### 测处理函数与测路由要分开

直接reply(recorder, request)只检查函数行为，不自动验证GET/POST规则。要验证405、404，先创建mux并登记，再调用mux.ServeHTTP(recorder, request)，这样才实际经过匹配。否则可能把“测试忘了走路由”误认为标准库不会返回405。

NewServer需要一个Handler。mux满足；普通函数可通过http.HandlerFunc(reply)适配。测试用server.URL，不固定18080；defer server.Close()收尾。第一轮先完成Recorder，第二轮再做Client超时/连接测试。

### t.Error与t.Fatal、测试能证明什么

t.Errorf记录失败后继续当前测试；t.Fatalf记录失败并结束当前测试goroutine。前置数据都没准备好时用Fatal，多个独立输出项不符可用Error继续收集。测试函数签名、_test.go后缀和go test的发现规则要对应。

先让一个期望写错，看到测试失败；恢复后再通过。改掉正式处理器空name校验，确认本题回归能发现；仅测试正常输入不能证明失败路径。

内存测试不证明真实端口、代理、TLS或网络都正常。NewServer补一层本机HTTP传输，也不能代替生产验收。状态Code、客户端Response.StatusCode、服务端WriteHeader三者在此形成对应。

## 与本题相连的原理和工程做法

### 测试从可证伪行为出发

测试名称应表达结果，例如“停用设备不能创建新任务”，而不只是“TestCreate”。正常、缺字段、越权、重复、并发、取消分别可能导致不同失败。

单元测试隔离业务规则；HTTP 测试检查协议；数据库集成测试检查真实约束与方言；端到端测试串联完整链路。SQLite 上通过不能证明 MySQL 的锁、JSON、时间类型或占位符行为相同。

检查错误优先看最近改动，再用最小输入复现；明确预期与实际差别后补失败测试，再改代码。不要把整片错误捕获后返回空列表来“修复”500，因为这会把系统故障变成假数据。


### 从读懂到会写，不要求一步跳过去

第一遍：能用箭头写出“请求头字符串 → 规范化函数 → 局部变量 → 响应头”。  
第二遍：将嵌套调用拆开，分别打印类型或在编辑器悬停查看签名。  
第三遍：自己实现一版明确合同的 normalize 函数，并处理空值、非法值。  
第四遍：把重复操作抽成中间件，让多个路由复用，[第 20 题讲义](../20-chi-router/知识串讲.md)。


普通请求测试稳定后，再做[响应状态与统一日志](响应状态与统一日志.md)，理解自动404/405与最终状态从哪里记录。
