## 这题在完整业务中的位置

批次一致性：避免一组资料只保存了一半。 [查看完整业务](../../业务主线.md)。

## 这次做成什么

用事务保证一次批量新增不会只保存一半。

## 具体需求

输入两台设备，先完成格式校验，再在同一个事务内插入。两条都成功才 Commit；任一失败就 Rollback 并返回原因。所有写入使用 tx，不能误用 db。故障用第二条 IP 与库中已有 IP 冲突来制造。

## 输入与结果

```text
两条 IP 均未占用 → 增加 2 行
第一条可用、第二条冲突 → 增加 0 行
```

## 怎样算完成

- [ ] 全成功时两条都存在。
- [ ] 第二条发生数据库唯一约束错误后，第一条也不存在。
- [ ] 重试失败批次仍无残留；事务失败后正常插入仍可成功。

## 本题常用写法（遇到再看）

```go
tx, err := db.BeginTx(ctx, nil)
```

- 【习惯】`tx` 是 transaction 的常用缩写；nil 参数在这里表示默认事务选项。
- 【库合同】事务内操作调用 tx.ExecContext；db.ExecContext 不会因为处在同一个函数里就自动加入该事务。
- 【常见组织】为退出路径安排回滚，并检查 Commit；成功提交后的重复 Rollback 可得到 sql.ErrTxDone，应与真正回滚故障区分。
- 【错误表达】补充上下文常用 `fmt.Errorf("保存设备失败: %w", err)`；%w 包装原始错误，调用者仍可用 errors.Is/As 判断。
