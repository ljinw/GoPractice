# 25 · 让停用设备退出后续巡检

阶段：业务闭环。前置：第 24 题。

## 先学再练：本题串讲

打开本目录的 [知识串讲](知识串讲.md)，先学这题需要的语法、原理和常用写法，再回来实现下面的业务需求。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

维护中的设备不应继续接受新巡检任务。

## 这次做成什么

把已学的 enabled 更新能力接成可用接口。

## 具体需求

PATCH /devices/{id}/enabled，正文 {"enabled":false}；成功 200 返回设备，缺少 enabled 或 null 为 400，设备不存在为 404。复用第 24 题的存储函数；能区分“没提供字段”与“明确传 false”。

## 输入与结果

```text
PATCH /devices/1/enabled + {"enabled":false} → 200，enabled=false
```

## 怎样算完成

- [ ] true→false 与 false→true 都能通过接口保存。
- [ ] {}、null 字段、错误类型均为 400，原值不变。
- [ ] 重复提交同一值不新增设备，另一台设备不变。

## 本题常用写法（遇到再看）

【常用写法】输入用 *bool 可区分缺失与 false；响应继续用 bool。【业务约定】enabled 控制新任务是否可提交，不修改已有报告。
