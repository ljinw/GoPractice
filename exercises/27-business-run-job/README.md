# 27 · 执行巡检并留下可核查的事实

阶段：业务闭环。前置：第 26 题。

## 业务为什么需要它

一个“异常”标签需要说明测到了什么。

## 这次做成什么

运行指定任务，持久化标准化事实与执行状态。

## 具体需求

内部 RunJob(ctx, jobID) 读取任务快照，从 fixtures/inspection-samples.json 的固定映射获得教学样例。queued 原子变为 running；完成后保存 cpu_percent、observed_at、source、fact_id 并成功结束。CPU >=80 判异常、<80 正常、null 未知；80 仅为教学阈值。文件损坏是执行失败，缺指标是未知。客户端不可传任意文件路径。

## 输入与结果

```text
sw-core → cpu_percent=92、异常；sw-missing → null、未知
```

## 怎样算完成

- [ ] 正常、异常、缺指标三个样例得到对应判断和事实编号。
- [ ] 坏样例使任务 failed，并留下原因，不能生成“正常”。
- [ ] 两个调用同时执行同一 queued 任务，只有一个获得执行权。

## 本题常用写法（遇到再看）

【常用写法】Collector 是采集能力接口，FakeCollector 提供本地样例。【业务区分】执行成功和设备正常是两种状态。
