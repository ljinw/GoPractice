## 标准库逐步读：从URL到一个字符串

先复习[01题的fmt与log](../01-http-health/fmt与log详解.md)及[请求/响应类型](../01-http-health/知识串讲.md#native-http)。本节说明自己写处理逻辑前必须知道的API；演示不直接替你实现本题所有验收。

### 把一条请求拆成不同部分

GET /hello?name=sw-core中，方法是GET，路径是/hello，查询字符串是name=sw-core。登记路由用GET /hello；查询参数不是把整个?name=...写入固定路由规则。

r.URL是*url.URL，r.URL.Path是string，r.URL.RawQuery是未解析的查询文本。r.URL.Query()解析参数并返回url.Values；它本质上是map[string][]string，因为同一个键可以出现多次。Get("name")只取关联的第一个值，缺失时返回空字符串。

~~~go
func (u *URL) Query() Values
func (v Values) Get(key string) string
func TrimSpace(s string) string
~~~

前两行属于net/url包，最后一行属于strings包。Query是URL对象的方法；Get是参数集合的方法；TrimSpace是包函数。Get没有第二个error返回值。URL.Query会忽略无法正确解析的参数部分；若业务要区分查询编码错误，应另外学习url.ParseQuery返回的error，不把Query当作严格输入验证器。

### 链式调用逐步展开

以下都放在已有处理函数内部，r由HTTP服务传入：

~~~go
requestURL := r.URL
values := requestURL.Query()
rawName := values.Get("name")
name := strings.TrimSpace(rawName)
~~~

输入/输出依次是：请求→URL对象→参数集合→字符串→整理后的字符串。name := r.URL.Query().Get("name")只是省略中间变量，没增加另一种机制。它不包含TrimSpace，整理仍需另外做。

strings.TrimSpace删除两端Unicode空白，返回新字符串，不会把原字符串变量自动改掉。因此name = strings.TrimSpace(name)是将返回结果重新赋给已有变量；不是调用一次就必然改变name。

空字符串、缺失name与全空白输入在本题都无效，所以整理后统一比较name == ""。比较用==；给变量重新赋值用=。错误分支先写400回复，再return，避免后续成功正文继续追加。

### 完整小实验：先在内存解析，不开HTTP端口

保存为本题warmup/query/main.go，运行go run ./warmup/query/main.go。

~~~go
package main

import (
    "fmt"
    "log"
    "net/url"
    "strings"
)

// main把URL、查询集合、原始值和整理结果分开观察。
func main() {
    u, err := url.Parse("http://127.0.0.1/hello?name=%20sw-core%20")
    if err != nil {
        log.Print(err)
        return
    }

    values := u.Query()
    raw := values.Get("name")
    cleaned := strings.TrimSpace(raw)

    fmt.Printf("路径=%q，原查询=%q\n", u.Path, u.RawQuery)
    fmt.Printf("原名称=%q，整理后=%q\n", raw, cleaned)
}
~~~

预期路径/hello，原查询保留%20，原名称两端是空格，整理后是sw-core。url.Parse返回(*url.URL, error)，所以先查err再用u；它与Query返回值数量不同。

### 回到HTTP时怎样选择输出与错误

处理函数里fmt.Println(name)打印到服务终端；fmt.Fprintln(w, name)才写HTTP正文。本题需要返回“已收到设备：名称”，可先用Sprintf生成文字，再交给Fprintln；也可用Fprintf，但要接住写入error。

http.Error(w, "name 不能为空", http.StatusBadRequest)可以满足本题纯文本错误要求。它没有error返回值，之后要return。下一题若要求错误JSON，应按JSON合同选择写法，不能把所有HTTP错误都机械换成纯文本。

### 反复练与源码问题

先用正常name、缺name、name=、name=%20%20四种输入画出每步值；再用name=a&name=b解释Get只取第一项。还可比较%20和+在查询解码中的表现。每次只变一项。

最后合上代码，把链式调用拆开写回来，解释每个变量的类型。读url.Values.Get源码，找“没有这个键返回什么”和“有多个值取哪一个”；读TrimSpace，先看合同再追一个分支。C#对照Request.Query/字符串整理时，核对空值与多值合同，不把API名字当成等价证明。

## 与本题相连的原理和工程做法

### 变量、零值、判断：别只认符号

`x := 1` 用于函数体内的短变量声明；`x = 2` 给已有变量赋值。`var count int` 创建整数变量并使用零值 0。`var enabled bool` 的零值是 false；string 的零值是空字符串。零值是语言提供的初始值，不一定等于业务上的“合法默认值”。

`if enabled { ... }` 要求条件是布尔值。`==` 比较，`=` 赋值，`!=` 表示不等。Go 不会把非零整数自动当成 true。尽早返回错误能减少嵌套：先拒绝非法输入，剩下代码处理正常情况。

对设备 CPU 数据来说，0 表示一次有效的 0% 采样；缺失则应使用额外状态或可空字段。直接把缺失解析成 0，会把“没采到”误报为“正常”。

### 本题的HTTP合同与数据流

本题只约定 GET /hello?name=sw-core：先取name，再去掉两端空白。合法时返回200和“已收到设备：sw-core”；缺失、空字符串、纯空白都返回400和“name 不能为空”。这时还没有写数据库或创建后台任务。

在处理函数里，r.URL.Query().Get("name")得到字符串，strings.TrimSpace返回整理后的新字符串；if只判断整理后的结果。错误分支通过w写错误响应，再return结束当前Go函数。return并没有把HTTP正文交给浏览器，正文来自对w的写入。

练习时分别写“URL输入→整理后的name→进入哪个分支→状态码与正文”。只看终端打印不能证明浏览器收到正确响应。其余状态码、JSON输入和权限在后续业务逐步加入。
