# 38 · 换端口后仍能找到设备服务

阶段：etcd 服务发现。前置：第 37 题。

## 先学再练：本题串讲

打开本目录的 [知识串讲](知识串讲.md)，先学这题需要的语法、原理和常用写法，再回来实现下面的业务需求。

配套：[多轮练习册：变式、排错、源码与C#](练习册.md)。先完成当前小步骤，再按练习册安排重复与复习。

## 业务为什么需要它

服务重启可能换地址，调用方不应到处写死端口。

## 这次做成什么

通过服务名解析 inventory 当前实例。

## 具体需求

使用本地 etcd 与匹配 Kratos 版本的 registry 集成。inventory 注册服务名、实例 ID、地址；inspection 按服务名发现。先只练一个实例重启换端口，继续使用它自己的原数据库；不用此题引入跨主机 SQLite 共享。注册租约失效后，旧实例应不可再用。

## 输入与结果

```text
inventory 从 19091 换到 19092 → discovery 更新后原调用方恢复请求
```

## 怎样算完成

- [ ] 不修改调用方地址即可找到新实例。
- [ ] 旧实例失效后在约定发现期限内移除，不无限等待旧端口。
- [ ] 注册中心故障有明确行为与日志，不返回虚构成功。

## 本题常用写法（遇到再看）

【常见名字】registry、discovery、serviceName、instanceID。【合同】发现“在哪里”不等于确认“这次调用成功”。
