## 与本题相连的原理和工程做法

### SQL 参数、NULL 与时间类型

参数绑定把值作为数据传给数据库，不能用字符串拼接用户输入。表名、排序字段等标识符通常不能通过普通占位符绑定，应使用明确白名单。MySQL 驱动常用 ?；PostgreSQL 常用 $1 等，不能把一套 SQL 不经检查换库运行。

SQL NULL 表示未知或缺失，不能用 = NULL 判断，使用 IS NULL。Go 对可空列需要相应可空类型或指针策略。时间要决定时区、精度和展示规则；应用、数据库、日志时区不一致会严重干扰排障。


### 先观察一个会错的过程

任务 running_count 初始为 0。A 读取 0，B 也读取 0；A 写 1，B 再写 1，最终只记了 1 次。这叫丢失更新。给两段代码分别加事务，不一定自动解决这个读后覆盖的问题；要看隔离级别、SQL 写法和并发控制。

原子 UPDATE 自增可以避免此类“读旧值再覆盖”。若是更复杂的状态转换，可以用条件更新：只允许 queued→running，检查受影响行数。受影响 0 行可能表示状态已变，也可能资源不存在；根据权限与业务合同再查询或返回冲突。
