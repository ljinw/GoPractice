## 业务为什么需要它

更新 API 镜像不能顺手丢掉设备、任务和报告。

## 这次做成什么

验证容器生命周期与业务存储生命周期分离。

## 具体需求

为既有项目构建可追溯镜像，记录平台、构建条件与启动用户；明确数据库/报告目录卷挂载。重建 API 和依赖容器时保留教学数据，检查健康与权限。镜像不含 .env、数据库和秘密；不执行删除卷作为普通重启。

## 输入与结果

写入假报告→重建API→保留卷重建数据库容器→仍可读取同一报告。

## 今天从这里动手

1. 先核对第40题网络和服务名，再列持久数据落点。
2. 按本项目实际入口与 CGO 条件调整构建模板。
3. 备份教学数据，逐个重建容器并跑业务回归。

## 怎样算完成

- [ ] 镜像版本/digest可追溯，运行配置和数据在镜像外。
- [ ] 两次重建后业务编号、正文及权限不变。
- [ ] 依赖故障时有界超时，卷权限错误能定位且不伪造成功。
