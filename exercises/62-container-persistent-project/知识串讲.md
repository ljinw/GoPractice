## 带着项目问题读原理

### 镜像、容器、卷、网络分别是什么

镜像是构建后的文件系统与启动配置；容器是运行实例；卷保存需要跨容器生命周期保留的数据；网络决定实例如何互相访问。删掉容器不应等于删掉业务数据，但数据是否真在卷里必须核对挂载。

镜像版本、配置版本、数据版本是三个维度。镜像不自动包含宿主机的配置、数据库和秘密。用同一个可追溯镜像从测试晋级到生产，才能说明“发布的就是已经验证的产物”。

多阶段构建把编译环境与运行环境分开，只把所需产物放进最终镜像。[Docker 多阶段构建](https://docs.docker.com/build/building/multi-stage/)。Go 程序是否能用极简镜像，需要检查 CGO、动态库、CA 证书、时区与运行用户，不能只根据“Go 能静态编译”下结论。

### 读懂 Dockerfile 的输入与产物

以下是模板片段，需要提供已核验并固定 digest 的 GO_IMAGE、RUNTIME_IMAGE；假定项目入口是 ./cmd/api，代码不依赖 CGO，运行镜像有需要的证书等文件：

~~~dockerfile
ARG GO_IMAGE
ARG RUNTIME_IMAGE

FROM ${GO_IMAGE} AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -o /out/api ./cmd/api

FROM ${RUNTIME_IMAGE}
COPY --from=build /out/api /app/api
USER 65532:65532
EXPOSE 8080
ENTRYPOINT ["/app/api"]
~~~

ARG 是构建参数；FROM 选择基础镜像；WORKDIR 决定后续相对路径；COPY 复制构建上下文；RUN 在构建时执行；ENTRYPOINT 是容器启动时执行。EXPOSE 记录端口意图，不等于已把端口发布到宿主机。

非 root 用户需要对写入目录拥有适当权限。构建上下文要通过 .dockerignore 排除密钥、数据库、日志和无关目录；构建参数也不适合承载应保密的长期凭据。

### Compose 中三个最常见误解

服务之间用网络中的服务名和容器端口连接。Go 容器里的 localhost 不是数据库容器；宿主机发布端口也不是所有内部连接都要经过的端口。

depends_on 表达启动依赖，是否等待健康要看配置和版本；即使最初等到了健康，依赖运行中仍可能失败，应用仍需超时与重连策略。容器 running 不等于业务 ready。

数据卷不是备份，镜像重建不等于数据库迁移，docker compose down -v 会删除关联卷，不能当成常规“重启”。保留数据时应区分停止、重建实例和删除存储。

已配置 Docker 的 PowerShell 或 Linux 可使用这些只读检查：

~~~text
docker compose ps
docker compose logs --tail=100 api
docker inspect <容器名>
~~~
