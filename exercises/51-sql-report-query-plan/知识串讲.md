## 本题在项目中的位置

报告积累后列表变慢，用户需要稳定地查看最近报告。

本题只推进这个结果：优化已有报告列表的一种固定查询形状。

## 先复习已经用过的写法

复习切片、Scan、Rows.Close 与 Rows.Err；ORM 返回了对象仍要看它执行的 SQL。

## 这次新增的知识

执行计划是优化证据；索引选择服务于具体查询，不靠口诀替代测量。

## 带着项目问题读原理

### 一个列表接口为什么越来越慢

假设任务表增长到百万行，接口每次按租户筛选状态、按创建时间倒序，取最近 20 条。数据少时全表扫描也快，数据多后才暴露问题。优化必须记录数据量、分布、SQL、参数、并发、耗时与结果正确性。

连接池等待、锁等待、磁盘读、排序、网络传输、JSON 编码都可能贡献延迟。先分段测量，再看数据库执行计划，不要看到接口慢就加索引或加 Redis。

### 联合索引要和查询形状一起看

针对 reports 表：

~~~sql
SELECT id, job_id, created_at
FROM reports
WHERE tenant_id = 7 AND status = 'ready'
ORDER BY created_at DESC, id DESC
LIMIT 20;

CREATE INDEX idx_reports_list
ON reports(tenant_id, status, created_at, id);
~~~

前两列是等值过滤，后两列支持稳定排序，这是本查询的候选设计，不是所有列表通用索引。是否有效还要看选择性、统计信息、返回列和执行计划。索引也要写入、占磁盘；多个相似索引会增加维护成本。

不能把“最左前缀”口诀当成优化器所有行为的完整解释。有些数据库版本与执行策略可能采用其他访问方式；最终要看计划和测量。对索引列做函数运算、隐式类型转换、前导通配符等，可能影响高效查找，需要按实际 SQL 验证。

### 先看 EXPLAIN，再解释耗时

关注访问方式、选中索引、估计行数、过滤条件、排序/临时结果。估计与实际差很多可能与统计信息、分布倾斜有关。EXPLAIN ANALYZE 会真正执行受支持的语句并收集运行信息，不能当成完全无副作用的解释按钮。[MySQL EXPLAIN](https://dev.mysql.com/doc/refman/8.4/en/explain.html)。

在测试库生成足量合成数据：多数租户小，少数租户大；有热门状态，也有冷门状态。记录加索引前后相同条件下的结果和耗时，分清缓存预热与优化效果。不要只拿两行数据证明优化成功。

深分页 `OFFSET 500000` 可能处理大量跳过的数据。游标分页用上一页末尾的 created_at 与 id：

~~~sql
SELECT id, job_id, created_at
FROM reports
WHERE tenant_id = 7 AND status = 'ready'
  AND (created_at < ? OR (created_at = ? AND id < ?))
ORDER BY created_at DESC, id DESC
LIMIT 20;
~~~

这种设计需要稳定排序和清晰的翻页合同；它不自然支持任意跳到第 12345 页，也不自动得到某时刻的完整快照。产品需求与查询方式要一起确定。

### ORM 不会替你决定数据库正确性

GORM 让结构体与查询更方便，但你仍要看生成的 SQL、WHERE、事务和受影响行数。传统 API 中用结构体 Updates 默认忽略零值；想把 enabled 改成 false，需明确选择字段或使用适合的 map 更新，而不能只看对象里 false 已赋值。[GORM 更新合同](https://gorm.io/docs/update.html)。

N+1 查询是查 20 份报告后再为每份报告单独查设备。可以批量查关联、预加载或按需求 JOIN，但 JOIN 也可能扩大行数，导致分页重复和计数错误。先决定页面要哪些字段，再选择查询策略。


## 把例子接回现有项目

在相同隔离库生成可重复的合成数据，固定租户/状态过滤和 created_at、id 稳定排序。记录 SQL、执行计划、扫描量与耗时，选择合适联合索引；深分页对照游标方案。保留租户隔离和字段合同，不能以少返回数据来伪造优化。

### 输入如何走到结果

同一租户最近20份 ready 报告：优化前后返回同一组 ID、相同顺序。

### 分步动手

1. 先建立慢查询基线，避免只有两行数据。
2. 按讲义阅读计划，再只改一处索引或查询。
3. 热/冷缓存条件分开记录，并跑其他租户及空列表回归。

### 读完后检验是否理解

先口述本题输入、需要改变的模块、权威数据在哪里、失败怎样被发现，再去 [需求与验收](README.md) 实现。讲义配置和表名是示意，先核对已有项目再使用；一处知识卡住可以单独练小片段，业务验收仍以实际运行证据为准。
