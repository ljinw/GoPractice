## 业务为什么需要它

报告事实告诉你发生了什么，知识条目帮助给出有出处的下一步。

## 这次做成什么

检索相关知识并把引用带入分析。

## 具体需求

使用 fixtures/knowledge.json 的三条教学知识；先实现本地关键词 Retriever，无需向量数据库。最多返回 2 条，保留 kb_id 与版本；模型结果中的 knowledge_ids 必须来自本次检索。无匹配时保留缺证说明。未来要换向量检索时单独加 Embedding/Indexer 练习，不改变本题证据约束。

## 输入与结果

```text
CPU 92 → 检索 KB-CPU-001；无关查询 → 空列表并明确没有依据
```

## 怎样算完成

- [ ] 相关问题检索到预期条目，无关问题得到空结果。
- [ ] 模型伪造知识编号或引用未检索条目时拒绝保存。
- [ ] 知识文本里的“忽略规则”被当资料内容，不能修改系统约束。

## 本题常用写法（遇到再看）

【概念】RAG 是先检索再生成；Retriever 是检索能力接口，Embedding/向量库只是可能的实现方式。
